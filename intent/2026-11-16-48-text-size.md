# Intent: Text size keys make the panel's text bigger or smaller

## Problem

The panel's text size can't be changed from the panel. Every size comes from
the Omarchy theme: titles, rows, captions and footer use `Style.font.title`,
`Style.font.body` and `Style.font.caption` (`ActionsPanel.qml:262`, `:270`,
`:327`, `:336`, `:346`, `:357`, `:368`, `:377`). Row heights, indents and the
icon column use `Style.space(...)` (`:314`, `:319-323`, `:330`). The card's
size is capped by `Style.space(900)` × `Style.space(680)` and the screen
(`:219-220`).

So the only way to get bigger or smaller text is to change the theme's font
size, which changes every Omarchy menu, or the screen scaling. On a large or
distant screen the run and step rows can be hard to read. On a small screen
long run titles and step names are cut off (`elide`, `:337`, `:347`, `:358`),
and you'd sometimes take smaller text to see more.

The keyboard reference (`keybindings.sh`) and the footer (`:374`) list no
size keys, because none exist.

This is deliberate today. The approved #22 intent says scale always follows
the theme and the panel adds no scale factor of its own
(`intent/2026-09-24-22-screen-scaling.md:57-60`), and the QML smoke test
asserts it (`tests/qml-smoke.py:91`, `panel.textScale===undefined`). The
README promises theme-sized text (line 3). #48 asks to supersede that rule
with a local adjustment the user controls, starting from the theme size.

## Proposed outcome

- While the panel is open, one key makes its text bigger and another makes
  it smaller, in steps, and a third key puts it back to the theme's size.
- At every allowed step, text stays readable within its row: no row's text
  is cut vertically, rows don't overlap, the tree's levels stay
  distinguishable, and the status information on the right stays usable.
  Long names may still be shortened with an ellipsis, and the list may still
  scroll, as today. The card stays within the screen, and at least a few rows
  of the list stay visible on a typical laptop screen.
- Size changes take effect at once, keep the selected row and the expanded
  rows, and keep the selected row in view.
- The size can't go past a smallest and a largest step, so the panel can't
  become unreadable or overflow.
- The new keys appear in the keyboard reference sheet and the README key
  table. They act only inside the popup. Using them never changes the search
  text.
- At the default step the panel looks exactly as it does today.

## Affected users and systems

- Anyone using the panel on a large, distant or small screen, or who wants
  more or fewer rows on screen.
- `ActionsPanel.qml` (sizes and key handler), `keybindings.sh`, `README.md`
  (key table and the theme-sized text promise on line 3), and
  `tests/qml-smoke.py` (the `textScale===undefined` check at line 91 changes;
  #47's real key events, if merged first).
- The #22 rule that the panel adds no scale factor of its own.
- Overlaps #42 (keys, footer, status line, row layout) and #46 (detail pane
  sizes). Lands after #42.

## Constraints

- Theme-native: sizes stay relative to the theme's own sizes, so a theme
  change still changes the panel, and the default is exactly the theme size.
  No fixed pixel sizes. This supersedes #22's "no panel scale factor" rule
  only for the user's own adjustment.
- Keyboard-first; keys must not clash with the panel's existing or approved
  keys (#42 adds `y`, `?`, `g`, `G`; #43 `m`; #44 `v`, `w`; #45 its action
  keys; #46 `i`), or with typing in the search field.
- No database or token storage (README line 3). Whether the size is
  remembered, and so whether any storage is needed, is open question 2.
- No change to other Omarchy menus or the theme.

## Open questions

1. **Which keys?** Options: `Ctrl+=` / `Ctrl+-` / `Ctrl+0` (browser habit),
   `+` / `-` / `0`, or `Ctrl+Plus` / `Ctrl+Minus`. Plain `+`, `-` and `0` are
   valid search characters, so they could only work outside the search field.
2. **Do the keys work while typing in the search field?** If yes, they must
   be keys that can't be typed into a search.
3. **Is the size remembered?** Options: only until the panel closes; for as
   long as the shell runs (it stays loaded, `manifest.json:6`); or across
   restarts, which needs storage the plugin avoids today.
4. **Range and step size?** For example five steps below and five above the
   theme size, or a range set as percentages of the theme size.
5. **Does the card grow with the text?** Options: the card keeps its size and
   shows fewer or more rows; or the card grows and shrinks too, up to the
   screen.
