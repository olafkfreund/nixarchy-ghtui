# Intent: Run and step timers tick every second

## Problem

The README promises "live status and timers", but the elapsed time shown for
running workflow runs, jobs and steps only changes when a reply from GitHub
arrives. Between replies it stays frozen.

`ActionsPanel.qml` keeps a `now` property and updates it every second
(the 1000 ms `Timer`). The row text, including each duration from
`duration(item, now)` in `ActionsModel.js`, is built only in `rebuild()`.
That runs on replies, navigation and filter changes. Nothing rebuilds the rows
when `now` changes, so the only thing that uses the 1-second tick is the
"GitHub paused until" cooldown text.

As a result, a running item's timer stays the same until the next poll
(about 5 to 15 seconds, depending on what is selected), then jumps
forward. The panel looks stalled even when the run is healthy.

## Proposed outcome

- While the panel is open, the elapsed time on every running run, job and step
  goes up by one second each second, with no gaps and no jumps.
- Finished items keep their fixed duration.
- Status still only changes when GitHub reports it.

## Affected users and systems

- Anyone using the panel to watch a workflow that is running.
- `ActionsPanel.qml` and possibly `ActionsModel.js` in this repository.
- Tests in `tests/`, which may need a case for the ticking timers.

## Constraints

- No extra GitHub API requests. The timers only use data the panel already
  has. Polling in `Polling.js` stays as it is.
- The tick must not reset or move the selection or cursor, and must not change
  the scroll position.
- Keep the CPU cost small while the panel is open. No work when it is closed.
- The existing tests in `tests/` must keep passing.
