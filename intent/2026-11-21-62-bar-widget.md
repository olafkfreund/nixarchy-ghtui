# Intent: A bar indicator for running and failed workflow runs

## Problem

You only learn that a workflow is running, or that a default branch
failed, by opening the panel. Issue #62 (split out of #46) asks for a bar
widget that shows this without opening the panel, and notes that polling
while the panel is closed is limited to watched runs (#44).

The sister plugin solved the same request in nixarchy-gltui #41
(v1.16.0): a second, widget-only plugin that reads a small status file the
panel writes. The same constraints hold here:

- **The plugin is a panel only.** `manifest.json` declares `"kinds":
  ["panel"]`, `ActionsPanel.qml` and `keepLoaded: true`.
- **Adding `bar-widget` to this plugin would change how it is enabled.**
  For a plugin with that kind, `omarchy plugin enable` puts it in the bar
  layout instead of `plugins[]`, and `listPlugins` reports it enabled only
  while it is on the bar (the Omarchy shell's `PluginRegistry.qml` and
  `shell.qml`, as found for gltui #41).
- **Entry points cannot see each other.** A third-party plugin's shell
  facade can toggle only its own id and reach only its own `service`
  entry point; a bar widget cannot read the panel's state directly.
- **The panel can already be toggled from outside**
  (`omarchy-shell shell toggle olafkfreund.github-actions '{}'`).
- **Data goes stale while the panel is closed.** `Polling.close` clears
  every task; only watched runs are polled while closed (#44). A
  repository's running count (`r.active`) and its default-branch result
  (`r.last`, from `lastResult()`) stay as they were at close, except
  where a watch reply updates them.
- **"Failed" already has a meaning here.** Each repository row shows the
  latest completed default-branch run the panel has seen (`r.last`, the
  highest run id seen; cleared when the default branch changes; a newer
  in-progress run does not replace it). A row counts as failing when that
  run's conclusion is one of `FAILED` (`failure`, `timed_out`,
  `startup_failure`; `ActionsModel.js` lines 17 and 108-119), and
  archived, disabled, blocked and errored repositories are shown apart.
  A repository whose newest 30 runs are all on other branches has no
  `r.last`.
- **The panel's `updated` time moves on any reply** (account, run, jobs,
  log; `ActionsPanel.qml` line 295), so it does not say how old the
  repository counts are.
- **One account, checked on open.** The panel watches `github.com` only.
  Each `open()` re-checks the `gh` login before other reads; a different
  login clears repositories and watches (`Polling.js` lines 375-379); a
  permission error on that check lets polling go on with the login
  unverified. A switch while the panel is closed is not noticed until it
  opens again, while watches keep polling.
- **Stops and pauses.** `polling.auth` stops all reads after a sign-in
  or setup failure (also from a closed watch); `catalogueBlocked` stops
  discovery after a permission failure while cached repositories still
  poll; a rate limit sets a cooldown, also from a rerun or cancel reply
  that arrives after close. Below 1,000 and 300 remaining requests,
  background and watch polling slow 3× and 10× without a cooldown.
- **nixarchy installs the plugin** (its `github` plugin entry) and does
  not place third-party bar widgets.

## Proposed outcome

When this is done:

- **A bar widget** can be added to the Omarchy bar like any widget. It
  shows a GitHub glyph with `●N` running workflow runs and `✕N`
  repositories whose default branch last failed (the same marks as the
  gltui widget), in the urgent colour when something failed or polling
  stopped, and fits a vertical bar. The tooltip and accessible name spell
  out both units. Every screen shows the same counts, and more widgets
  add no requests.
- **"Failed" matches the panel:** the repositories the panel's rows mark
  failing (decision 2 below), never archived, disabled, blocked or
  errored ones.
- **A left click** toggles the panel; other buttons do nothing.
- **Clear states:** no data yet (dimmed glyph, "open the panel to
  load"), ok (including zero repositories after a completed discovery),
  stopped (sign-in, setup or discovery permission problem, reason in the
  tooltip), and paused by a rate-limit cooldown until a time, which
  clears by itself without opening the panel. The quota slowdown alone
  is not shown as paused.
- **Honest freshness:** the tooltip gives the time of the last repository
  activity read and says that watched runs are still checked on their
  schedule (every 30 s, slower when the quota is low). A watched run that
  finishes while the panel is closed updates the running and failed
  counts without moving that time.
- **Clean resets:** the widget shows no data when the panel loads and,
  as far as it can, when it unloads; a confirmed change of `gh` login
  clears the counts and their time. An unverified login does not block
  the counts.
- **The panel plugin is unchanged** in how it is enabled and listed;
  the widget is a separate plugin installed beside it (if decision 1
  holds).
- **The README** explains how to install, place and remove the widget
  and what its counts mean.

## Affected users and systems

- Users of the GitHub Actions panel who want a bar indicator.
- Files (with decision 1): `Polling.js` (a counts timestamp),
  `ActionsModel.js` (counts and status), `ActionsPanel.qml` (writing the
  status file), a new `bar-widget/` plugin, `flake.nix` (a `bar` package
  beside the panel's `default`, and checks), `tests/`, `README.md`,
  `manifest.json` (version only).
- Hosts: p620 and razer through the release and pin chain; p510 is not
  touched.
- nixarchy: no change needed to ship; installing the widget there is a
  follow-up, as for gltui.

## Constraints

- No extra GitHub requests: the widget never calls `gh`; while the panel
  is closed only watched runs are polled, as today.
- No daemon or token storage; the status file holds counts and short
  texts only, in the user's runtime directory.
- The panel plugin's id, enable and list behaviour stay as they are.
- Reuse gltui #41's design and file format where they fit (single host,
  so none of its multi-host aggregation or `shell.json` reading), so the
  two widgets behave alike, but port by hand.
- Text from GitHub or errors is shown as plain text; only the documented
  shell plugin API; no new runtime dependency.
- The QML smoke runs only in CI, never on the desktop.

## Open questions

1. **Shape.** Recommended: as gltui #41, a second widget-only plugin
   (`olafkfreund.github-actions-bar`) fed by a status file the panel
   writes, rather than a `bar-widget` kind on the panel plugin (which
   changes how the panel is enabled).
2. **What "failed" counts.** Recommended: repositories whose latest
   completed default-branch run seen (`r.last`) concluded with one of
   `FAILED` (`failure`, `timed_out`, `startup_failure`), excluding
   archived, disabled, blocked and errored repositories: exactly the rows
   the panel marks failing. The alternative, any failed run on any
   branch, would count pull-request branches.
3. **Polling while closed.** Recommended: none beyond today's watched
   runs; the widget shows counts as of the last read, with that time in
   the tooltip.
4. **Click.** Recommended: left click toggles the panel; no other
   actions.
5. **nixarchy placement.** Recommended: nixarchy does not install or
   place the widget in this issue; a follow-up can.
