# Plan: Remove the panel's dead code and duplicated logic

## Approved decisions

- **Baseline:** `main` after PRs #26, #27 and #28 merge. The line numbers
  below come from `main` (4f51f7f) with those three diffs applied; all three

- **Size:** about 160 lines removed in total. That is about 97 from

## Equivalence script

Save this as `$SCRATCH/eq/sequence.cjs`; it isn't committed. It's a scripted
20-minute run with 30 repositories. It covers:

- two catalogue pages
- a selection with an expanded run
- 14-run summaries, which exercise the trim
- a rate limit and a network failure
- close, and a reopen 5 minutes later

It prints every request `Polling.next` makes and the final run ids for each
repository. Two runs on the same file give identical output.

```js
// node sequence.cjs <Polling.js> : print every request Polling.next makes in a fixed scenario.
const fs=require('node:fs'), vm=require('node:vm'), p={};
vm.createContext(p); vm.runInContext(fs.readFileSync(process.argv[2],'utf8'),p);
const s=p.create(), repos=Array.from({length:30},(_,i)=>({repo:`org/r${i}`}));
const runs=n=>Array.from({length:n},(_,i)=>({id:100+i,status:i<2?'in_progress':'completed',run_attempt:1}));
let flight=null, out=[];
p.open(s,0);
for(let now=0; now<1200000; now+=250) {
  if(now===30000) p.select(s,'org/r1','101',{'org/r1:101':true},now,false);
  if(now===400000) p.close(s);
  if(now===700000) p.open(s,now);
  if(flight && now>=flight.end) {
    const q=flight.req, n=out.length; let r={requestId:q.requestId,data:[],nextPage:0,error:'',errorType:'',remaining:4000};
    if(n===40) r={...r,error:'GitHub rate limit',errorType:'rate',retryAt:now+30000};
    else if(n===55) r={...r,error:'GitHub request failed',errorType:'network'};
    else if(q.kind==='catalogue') { r.data=q.page===1?repos.slice(0,20):repos.slice(20); r.nextPage=q.page===1?2:0; }
    else if(q.kind==='run') r.data={id:Number(q.run),status:'completed',run_attempt:1};
    else if(q.kind==='jobs') r.data=[{id:1,status:'completed',steps:[]}];
    else if(q.repo==='org/r1' || q.repo==='org/r2') r.data=q.status==='in_progress'||q.kind==='activity'?runs(2):runs(14);
    p.complete(s,r,now); flight=null;
  }
  if(flight && now===400000) flight=null;
  const q=p.next(s,now);
  if(q) { out.push(JSON.stringify({at:now,...q})); flight={req:q,end:now+700}; }
}
console.log(out.join('\n'));
console.log(JSON.stringify(s.repos.map(r=>[r.repo,(r.runs||[]).map(x=>x.id)])));
```

I tried it on the post-#26/#27/#28 `Polling.js`. It makes 406 requests,
including 81 summary pages and 140 jobs requests. `org/r1` ends with its 2
running runs plus 10 completed ones, so the trim is exercised.

## Rollback

- Each of commits A–D stands alone and leaves the suites green. Revert the
  one at fault (`git revert <sha>`), or revert the PR's merge commit to undo
  all of #31.
- No state, config or migration is involved. After a revert, a user's
  shell.json `repositories` key is read again, and `actions.py summary`
  and the other old modes work again.
- If #30 or #32 were rebased onto #31 before a revert, they need a rebase
  onto the reverted `main`. Only their context lines are affected.
