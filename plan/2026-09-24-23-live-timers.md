# Plan: Run and step timers tick every second

## Approved decisions

- **Root cause:** `rebuild()` (`ActionsPanel.qml:69`) already passes `now` to
  `Model.rows(...)`, and `duration(item, now)` (`ActionsModel.js:19`) already
  computes the elapsed time from it. The 1 s `Timer` (`ActionsPanel.qml:202`)
  updates `root.now`, but nothing rebuilds the rows when `now` changes.
- **Fix, `ActionsPanel.qml` only, two edits:**
  1. Next to `onFilterTextChanged` (line 38), add:

     ```qml
     // ponytail: full rebuild at 1 Hz (~7 ms at 1650 rows in Node); skip when no entry has an open-ended duration if it ever shows in a profile
     onNowChanged: rebuild()
     ```

  2. Add `triggeredOnStart: true` to the 1 s timer, so the rows are fresh the
     moment the panel opens:

     ```qml
     Timer { interval: 1000; running: root.opened; repeat: true; triggeredOnStart: true; onTriggered: root.now = Date.now() }
     ```

- **Unchanged:** `ActionsModel.js`, `Polling.js` and `actions.py`. The fix adds
  no GitHub requests.
- **Cursor, selection and scroll are kept without extra code.** A tick
  changes only `info`, so the row keys and their order stay the same:
  - `Model.selection` returns the same index.
  - `syncRows` calls `setProperty` only on changed rows and returns
    `structureChanged === false`, so the `contentY` restore branch never runs.
  - Delegate height depends only on `subtitle`, which a tick does not change.
  - `rebuild()` never calls `selectionChanged()`, so `Polling.select` does not
    run.
- **CPU ceiling:** the timer runs only while `root.opened`, so a closed panel
  does no work. A tick is linear in the number of visible rows: when rows are
  aligned, `syncRows` finds each key on its first comparison. The worst case
  measured in Node (1650 rows, all repositories expanded) is about 7 ms per
  tick, about 0.7 % of one core. QML's engine is a few times slower than
  that, and the normal view (about 150 rows) is far cheaper. There is no
  "only when running" guard. The `ponytail:` comment names that guard as the
  upgrade if the cost ever shows up in a profile.
- **Alternatives rejected:**
  - A per-delegate binding to `now`: `rowData` has no raw timestamps, and row
    text would then be built in two places.
  - A separate duration model or role: the same drawback, plus a schema
    change to `visibleRows`.
  - Rebuilding from the timer's `onTriggered`: this hides the dependency on
    `now`, and the test could no longer drive it synchronously.
  - Polling more often: extra requests, and the timers would still jump.
  - A "running only" guard: not worth its cost (see the CPU ceiling above).
- **Accepted behaviour:** rows awaiting their final status, and queued runs
  that already have `run_started_at`, keep ticking. That is the last state
  GitHub reported.
- **Commit:** the test and the fix go in one commit,
  `fix: tick run and step timers every second (#23)`, on
  `fix/23-live-timers`. A PR links the intent, spec and plan.

## Steps

1. `tests/qml-smoke.py`: add the failing check to the stage-0 block, directly
   after `check(panel.current.kind==="run","keyboard selection")` (line 89).
   At that point the panel is closed, nothing is polling, and the run row is
   selected.

   ```js
   panel.polling.repos[0].runs[0].run_started_at=new Date(panel.now-5000).toISOString()
   panel.adopt()
   var tickKey=panel.current.key, tickCursor=panel.cursor, tickScroll=JSON.parse(panel.status()).scrollY
   panel.now=panel.now+3000
   check(panel.current.info==="8s","running duration ticks with now")
   check(panel.current.key===tickKey && panel.cursor===tickCursor,"tick keeps selection")
   check(JSON.parse(panel.status()).scrollY===tickScroll,"tick keeps scroll")
   ```

   → Verify on the current `ActionsPanel.qml` by running
   `python3 tests/qml-smoke.py`. It must exit non-zero with
   `CHECK FAILED: running duration ticks with now` in the output, because
   `info` is still `"5s"`. If it fails for any other reason, or passes, stop
   and revise the test before touching the panel.

2. `ActionsPanel.qml`: add `onNowChanged: rebuild()` with its `ponytail:`
   comment after the `onFilterTextChanged` block (lines 38-42).
   → Verify with `python3 tests/qml-smoke.py`. It must print
   `QML_CHECKS_PASSED` for both the `fresh` and `managed` scenarios, with no

3. `ActionsPanel.qml`: add `triggeredOnStart: true` to the 1000 ms `Timer`
   (line 202).
   → Verify with `python3 tests/qml-smoke.py`, which must still pass. Stage 1

`tests/model.cjs` needs no new case. Line 21 already covers `duration()` with
an explicit `now`, and lines 42-49 cover the in-place `syncRows` update that a
tick uses.
