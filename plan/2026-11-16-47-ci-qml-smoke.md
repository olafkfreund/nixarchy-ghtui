**Session bootstrap (spec).** The test never relies on runner session
defaults. It creates a private `XDG_RUNTIME_DIR` (fresh temp dir, mode
0700), writes a minimal explicit sway config (one headless output, no bar,
no autostart, no binding that runs a command), starts sway with `-c` and
`WAYLAND_DISPLAY` unset, waits for sway's own socket inside that directory,
then starts `quickshell -p <root>` and `wtype` with an environment built
from scratch: the private `XDG_RUNTIME_DIR`, that socket as
`WAYLAND_DISPLAY`, the Qt and wlroots variables above, `HOME`, and the
scenario's `PATH`. The caller's `WAYLAND_DISPLAY`, `HYPRLAND_*`, `SWAYSOCK`
and `DISPLAY` are never passed on. The test refuses to run if the socket it
waits for is not inside its own private directory. Teardown runs on every
exit path: terminate quickshell and sway, kill after a short grace period,
remove the temp directory.

**Flow (spec).** `shell.qml` (the temp one the test writes) keeps seeding
data; Python sends keys with `wtype`; QML only reports a state line on every
change, built from `panel.status()` plus `cursor` and `layout()`. The QML no
longer calls `panel.move()` or `panel.expand()`. Readiness before the first
key: wait for `opened`, then (if sway can show it) a mapped layer surface,
then send one harmless probe key (`k` at the top row, leaving `cursor` 0)
and wait for a state line proving it arrived (but see Deviations 4: this
probe changes no state). Every later wait uses only state lines whose
sequence number is greater than the key just sent, and, per step 3, each
predicate is a transition from the pre-key state. No fixed sleeps; each wait
has a timeout. The 25 s whole-run limit and 18 s stage timers are not
raised.

The fake helper appends one line per request (`kind`, `requestId`, `repo`)
to a file; refresh assertions read that file. Before each refresh key the
test waits until the initial summary chain has completed, the file has
stopped growing and no request is in flight, records the baseline, sends the
key, then requires a request of the exact expected `kind` beyond the
baseline, started soon after the key (step 4). (`r` does not queue
`activity`: `seed` deletes it when a summary exists.)

**Layout check (spec).** Add `layout()` to `ActionsPanel.qml` next to
`status()`, exactly:

```qml
function layout() {  // test hook: geometry of the delegates that exist
    var rows = []
    for (var i = 0; i < list.count; i++) { var item = list.itemAtIndex(i); if (item) rows.push({i: i, key: entries[i].key, x: item.x, y: item.y - list.contentY, w: item.width, h: item.height}) }
    return JSON.stringify({listWidth: list.width, listHeight: list.height, count: list.count, rows: rows})
}
```

The test fails when: `listHeight` or `listWidth` is 0 while `entries.length >
0`; `count` differs from `entries.length`; after a cursor move the selected
row's delegate is not in `rows`; the selected row has `w <= 0` or `h <= 0` or
does not satisfy `x >= 0`, `x + w <= listWidth`, `y >= 0`, `y + h <=
listHeight`; two rows overlap (`y[i] + h[i] > y[i+1]`); any seeded row, visited
one after another by `j` from `Home` to `End`, fails these in turn; the
selected row after `End` then `Home` is inside the list. Rows partly scrolled
out are expected and not a failure. The seeded data must overflow the list so
scrolling is exercised. No stored images.

**Failure scenarios (spec), same compositor.**
- *Helper cannot start:* `PATH` holds only `quickshell`, `sway`, `swaymsg`,
  `wtype`, no `python3`. The panel must reach `error === "python3 not
  found"`, `workerBusy` false, `polling.auth` true, and no further requests
  (`ActionsPanel.qml:147-151`, `onRunningChanged` `:203`, errorType `setup`
  from #24). Menu registration also uses `python3`; its failure is a log
  line, allowed and not asserted.
- *Close while a request runs:* the fake writes its pid then blocks until
  signalled. The test waits for the pid file and `inFlight`, sends `Escape`,
  and asserts `workerBusy` false, the pid gone within the existing wait, and
  the request count not rising afterwards. Any leftover fake pid is killed on
  every exit path. Removing `requestProc.running = false` (`:58`) must make
  this scenario fail.

**Failure messages (spec).** Keep #36's stage naming. Every key step carries
a label such as `key Escape in search field: expected editing=false got ...`.
On timeout print the stage, the last state line, and sway/quickshell output.

**Flake and CI (spec).** `checks.plugin` loses the invalid-directory block
(`flake.nix:80-83`); the rest stays. A new `devShells.default` lists
`quickshell`, `sway`, `wtype`, `python3`. The workflow gets a second job
`qml-smoke` with the same checkout and `install-nix-action` SHAs, same
`permissions: contents: read`, same 15 minute limit, running
`nix develop -c python3 tests/qml-smoke.py`. `tests/qml-smoke.py` keeps its
optional `plugin_dir` argument so it still tests `./result`.

## Repo traps that apply to the whole plan

- Argument arrays only: every `subprocess` call in the test is a list, no
  `shell=True`, no string commands; `wtype` is called as `["wtype", "-k",
  "Escape"]`. Shift+R is `["wtype", "-M", "shift", "-k", "r", "-m", "shift"]`
  (plain `wtype R` sends no Shift modifier, so the panel would see `r`).
- `plain()` and #32: no test or stub writes GitHub text into a QML property
  that renders as rich text. The panel's own `Text.PlainText` stays; the fake
  data contains only plain names.
- `github.com` pinning (#32): no URL other than `https://github.com/` appears
  in fake data; `o` is not pressed (it would run `xdg-open`).
- Fixed UI strings (#24): do not change `Model.reply`, `failedToStart` or any
  panel message; the failure scenarios assert the existing fixed string
  `python3 not found`.
- Qt 0.3.1 Process quirk (`ActionsPanel.qml:202`): a failed start emits
  neither `started` nor `exited`, only `running=false`. The helper-cannot-
  start scenario relies on `helperStarted`; do not "fix" it.
- Qt 6.12 shadows an unqualified `Color`: in `shell.qml` and in the stubs use
  `Commons.Color` (`import qs.Commons as Commons`), as #40 did in the panel.
- `shownFields` in `ActionsModel.js:93` decides which row fields cause a
  re-render. The test adds no field to rows. State lines that need `info` read
  `panel.current.info`, they do not add a row field.
- #36 no-rerun rule (decision 6) governs every "verify by" below.
- ponytail: smallest correct change. No new flake package, app, input, action
  or dependency; no helper class hierarchy in the test, plain functions.
- nixarchy owns the menu: `menu.py register` still runs against a temp `HOME`
  only; the test never touches the real `~/.config/omarchy`.
