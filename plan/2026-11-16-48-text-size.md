## Approved decisions (copied from the approved spec, with the owner's answers)

1. **Keys:** Ctrl+= bigger, Ctrl+- smaller, Ctrl+0 reset to the theme size. Ctrl+Shift+= (`Qt.Key_Plus`) also makes text bigger (kept alias). Shift is allowed with Ctrl. Ctrl with Alt or Meta is not taken. Keypad works (same keys).
2. **They work while typing in the search field and never change the search text.** The search field's `Keys.onPressed` runs before the field's own handling, so handling the key there first means it is never inserted.
3. **Remembered while the shell runs, no file.** One `int` property on the panel root. `close()` only clears `opened`; the plugin stays loaded (`keepLoaded: true`). A shell restart resets to the theme size.
4. **Range: -3 to +5, 10 points per step, 70% to 150% of the theme size** (owner answer: the spec's -5 became -3). Factor is `(10 + step) / 10`, linear, not compounding. A test asserts step -4 clamps to -3.
5. **The card keeps its size.** The card expression (`Math.min(Style.space(900), ...)`, `Math.min(Style.space(680), ...)`) does not change. More or fewer rows fit.
6. **Order: after #42.**
7. **Kept as specified (owner answers):** the `Key_Plus` alias, the "Text size N%" notice through #42's `showNotice()`, and the footer wrap above step 0.
8. **Match on `event.key`, not `event.text`** (Shift must not matter). No alias beyond `Key_Plus` is added blind: only add a `Qt.Key_*` if the layout check on razer shows it arrives.
9. **Everything stays relative to the theme.** `Style.font.*` and `Style.space()` are read live (theme, `base-size` and monitor scale changes still reach the panel). No fixed pixel sizes, no pixel floor.
10. **Not touched:** `entries`, `cursor`, `expanded`, `filterText`, `Polling`. The key only changes `textStep`, re-lays out the list and keeps the cursor row in view.

## Design in code

`ActionsModel.js` (pure, `node`-testable; add near `age()`):

```js
function clampStep(n) { return Math.max(-3, Math.min(5, Math.round(Number(n) || 0))) }
function zoomed(px, step) { return px > 0 ? Math.max(1, Math.round(px * (10 + clampStep(step)) / 10)) : 0 }
```

`ActionsPanel.qml` root (near `property double now`):

```qml
property int textStep: 0
readonly property int fTitle: Model.zoomed(Style.font.title, textStep)
readonly property int fBody: Model.zoomed(Style.font.body, textStep)
readonly property int fCaption: Model.zoomed(Style.font.caption, textStep)
property alias listView: list      // smoke test reads delegate geometry through it (omit if #47 has landed: use its layout())
function sp(n) { return Model.zoomed(Style.space(n), textStep) }
function textKey(event) {
    var m = event.modifiers
    if (!(m & Qt.ControlModifier) || (m & (Qt.AltModifier | Qt.MetaModifier))) return false
    if (event.key === Qt.Key_Equal || event.key === Qt.Key_Plus) setTextStep(textStep + 1)
    else if (event.key === Qt.Key_Minus) setTextStep(textStep - 1)
    else if (event.key === Qt.Key_0) setTextStep(0)
    else return false
    return true
}
function setTextStep(n) {
    textStep = Model.clampStep(n)
    list.forceLayout()
    list.positionViewAtIndex(cursor, ListView.Contain)
    showNotice("Text size " + (100 + 10 * textStep) + "%")
}
```

`Style.space()` and `Style.font.*` are `int` in the Omarchy tree (`shell/Commons/Style.qml`), so step 0 returns exactly the theme value.
