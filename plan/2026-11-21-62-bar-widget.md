## Decisions (from the approved spec)

1. **Shape:** a separate widget-only plugin `olafkfreund.github-actions-bar`
   in `bar-widget/`, fed by a status file the panel writes. The panel
   plugin's manifest stays panel-only.
2. **Status file:** `$XDG_RUNTIME_DIR/omarchy-github-actions-<WAYLAND_DISPLAY>.json`,
   `""` if either variable is empty (write nothing, show `none`), a
   property on both sides that tests override. Shape: `{version: 1,
   instance, account, state, running, failed, countsAt, cooldownUntil,
   reason, writtenAt}`; `state` ∈ `none`, `ok`, `stopped`, `rate`;
   `account` = `polling.accountVerified && polling.account ?
   polling.account : ""`. Written whole by a `FileView` with
   `atomicWrites: true`, `blockWrites: true`, `printErrors: false`.
3. **Counts** (`Model.barCounts(repos, now)` in `ActionsModel.js`): skip
   archived, disabled, blocked and errored repositories; `running` = the
   rows' per-repository number (`repo.active`, or the cached
   `in_progress` runs when unset); `failed` = repositories with
   `Model.health(repo, now, 0).status === "failure"` (`r.last.conclusion`
   in `FAILED`).
4. **Status** (`Model.barStatus(polling, instance, now, previous)`), first
   match wins: `stopped` with `reason` = `polling.error` when
   `polling.auth`, else `polling.catalogueBlocked` when set; `rate` with
   `cooldownUntil = polling.cooldown` when in the future; `none` when
   `polling.countsAt === undefined`; `ok`. Counts and `countsAt` in every
   state, except that in `rate` they are taken from `previous` (the last
   published payload) when it has `countsAt > 0`. The quota slowdown is
   not a state; transient errors are never read. The `rate` fallback to
   `previous` applies only while the repository cache is intact
   (`polling.countsAt !== undefined`): an account reset deletes
   `countsAt`, so a cooldown in the same reply that switched the login
   never shows the old account's counts. The payload always has every
   key, with `countsAt: 0` and `cooldownUntil: 0` when unset.
5. **`Polling.countsAt`:** a field in `create()` starting `undefined`
   (internally `0` is a valid set value; only the payload maps `undefined`
   to `0`); `activity()` sets it to `now`; the final catalogue branch in
   `completeReply()` (after the `nextPage` return) sets it when no
   repository is pollable by `seed()`'s rule (not archived, disabled or
   blocked); run, jobs, log, account and load-more replies never do; the
   account reset in `completeReply()` (different verified login) deletes
   it.
6. **Publishing** (`ActionsPanel.qml`): `statusPath` (from
   `Quickshell.env("XDG_RUNTIME_DIR")` and `Quickshell.env("WAYLAND_DISPLAY")`),
   `statusInstance`
   (set once at `Component.onCompleted`), `lastStatus`, `pendingStatus`,
   the writer and `publishStatus()`; writes only when the payload without
   `writtenAt` differs from the last successful write (recorded in
   `onSaved`; a failed save stays unrecorded; a `statusPath` change clears
   both). It passes the parsed last successful payload as `previous` to
   `Model.barStatus` and writes with `statusFile.setText(JSON + "\n")`.
   Called in `adopt()` before `if (!opened) return`; after
   `Polling.noteWrite` in `receiveAction`; in `open()` after
   `Polling.open()`; in `refresh()` after `Polling.manual()`; at
   `Component.onCompleted` (writes `none`); at `Component.onDestruction`
   (best effort, `none`).
7. **Widget view** (`BarModel.view(text, now, vertical)`): `none` for
   empty, unparseable, `version !== 1` or an unknown `state`; counts
   clamped to non-negative integers; `account` and `reason` used only if
   strings, cut to 100 and 120; an expired `rate` becomes `ok` if
   `countsAt > 0` else `none`; `active = state === "stopped" || failed >
   0`; `dimmed = state === "none" || state === "rate"`; glyph U+F09B
   written in the source as the six-character escape `\uF09B` (never the raw glyph); parts joined with `"\n"` on a vertical bar.
   States:

   | State | Label | Tooltip |
   | --- | --- | --- |
   | `none` | glyph | "Open GitHub Actions to load" |
   | `ok` | glyph, `●N` if running > 0, `✕N` if failed > 0 | "GitHub Actions · <account>" (or "GitHub Actions"), "N running workflow runs, N failing repositories", "Last repository activity read at HH:MM; watched runs are checked every 30 s, slower when the quota is low" |
   | `stopped` | glyph and `!` | "GitHub Actions stopped" + (": <reason>" if any) + ". Open the panel to fix it." |
   | `rate` | glyph and the last counts | "GitHub paused until HH:MM", then the `ok` lines when `countsAt > 0` |

   Singular and plural units; accessible name = tooltip lines joined with
   ", "; `HH:MM` zero-padded local time.
8. **Widget QML:** `Ui.BarWidget` with one `Ui.WidgetButton` filling it,
   `pressFeedbackButtons: Qt.LeftButton`; a left press runs
   `Quickshell.execDetached(["omarchy-shell", "shell", "toggle",
   "olafkfreund.github-actions", "{}"])`, other buttons nothing; a
   `moduleName: "olafkfreund.github-actions-bar"`; `text`, `active`,
   `dimmed`, `tooltipText` and `Accessible.name` bound from the view;
   `vertical` from the base; a `FileView` on `statusPath` (the same
   `Quickshell.env` path) (`watchChanges`, `printErrors: false`) →
   `view(text())` on
   load, `view("")` on a failed load, reload on change, `none` on
   `onStatusPathChanged`; a one-shot recheck `Timer` at `recheckAt`
   clamped to 100 ms … 24 h; plain text only.
9. **Manifest** of the widget: `schemaVersion: 1`, id, name "GitHub
   Actions bar", `version` = the panel's, `author`, `description`,
   `kinds: ["bar-widget"]`, `entryPoints: {barWidget: "BarWidget.qml"}`,
   `barWidget: {displayName: "GitHub Actions", category: "Development",
   allowMultiple: false, defaultSection: "right"}`, no `keepLoaded`; plus
   a `LICENSE` copy.
10. **Packaging:** `packages.<system>.bar` copies `bar-widget/`;
    `packages.default` stays the panel; `checks.plugin` checks the bar
    package (file list, no symlinks, id, kinds, entry point, version equal
    to the panel's) and runs `node tests/bar.cjs`.
11. **Version 1.2.0** in both manifests (set the panel's in step 3 with
    the widget's, so step 5's version check passes). **Rollout:** p620 and
    razer after release; p510 untouched; the QML smoke runs in CI only.
12. **Constraints:** one account (`github.com`), no `shell.json` reading,
    no extra GitHub requests, plain text, no new runtime dependency.

## Steps

1. **`Polling.countsAt`** — `Polling.js`, `tests/polling.cjs`. Decision 5.
   - Tests: activity sets it; an empty completed catalogue sets it; run,
     jobs, log, account and load-more replies leave it; a different
     verified login deletes it; a closed watch that finishes updates
     `r.active`/`r.last` without moving it.
   - Verify: `node tests/polling.cjs`.
   - Traps: summaries call `activity()` for their in-progress phase, so no
     separate summary hook.

2. **`barCounts`, `barStatus`** — `ActionsModel.js`, `tests/model.cjs`.
   Decisions 3 and 4.
   - Tests: skips archived, disabled, blocked, errored; counts the three
     failure conclusions; precedence auth → catalogue block → rate → none
     → ok; unverified account `""`; `rate` keeps `previous` counts after a
     rate-limited repository reply marked its repository errored, but not
     after an account reset in the same reply; a clock-zero `countsAt: 0`
     is `ok`, `undefined` is `none`; every payload key present.
   - Verify: `node tests/model.cjs`.

3. **Widget plugin** — new `bar-widget/manifest.json`, `BarWidget.qml`,
   `BarModel.js`, `LICENSE`; new `tests/bar.cjs`; root `manifest.json`
   version 1.2.0. Decisions 2, 7, 8, 9, 11.
   - `tests/bar.cjs` loads `bar-widget/BarModel.js` with `vm` like the
     other suites and covers every state, the unknown-state guard,
     clamping, string checks, empty reason, `active`/`dimmed` in `rate`
     with failures, expired rate, the vertical label and plural units.
   - Verify: `node tests/bar.cjs`.

4. **Panel publishing** — `ActionsPanel.qml`. Decisions 2 and 6.
   - Verify: `node tests/polling.cjs`, `node tests/model.cjs`, `node
     tests/bar.cjs` (each; a glob runs only the first); the lead checks CI.
   - Traps: `adopt()` returns early while closed; the publish call must
     come before that return. `receiveAction` calls `adopt()` only for an
     open success, so it needs its own publish after `noteWrite`.

5. **Packaging** — `flake.nix`. Decision 10. In `checks.plugin`, copy
   `BarModel.js` from the built `bar` package into a `bar-widget/`
   directory of the check's build tree before `node tests/bar.cjs`, as
   gltui's flake does.
   - Verify: the lead runs `nix build .#bar` and `nix flake check -L`.

6. **Smoke** — `tests/qml-smoke.py`, `tests/stubs/Ui/` (new `BarWidget.qml`,
   `WidgetButton.qml` stubs and `qmldir` entries).
   - Stubs carry the properties the widget uses: `BarWidget` has
     `moduleName`, `bar` and `vertical` bound to `bar ? !!bar.vertical :
     false`; `WidgetButton` has `text`, `active`, `dimmed`, `tooltipText`,
     `pressFeedbackButtons` and a `pressed(button)` signal. The widget
     import is staged only when `bar-widget/` exists.
   - Widget stage only when the source has `bar-widget/` (a `./result`
     run says it skipped it); the main panel and the stage's panel use
     separate status paths; a fake `omarchy-shell` on `PATH` logs its
     argv.
   - Checks: each state from a written file, an unknown state and a
     deleted file show `none`, two widgets agree, one left click logs one
     toggle line and right/middle log none, the panel writes `none` at
     start and on destruction, a closed watch that finishes changes the
     file's counts without moving `countsAt`, a late rate-limited action
     reply publishes `rate` while closed, and reopening clears a
     published stop; an unchanged payload keeps its `writtenAt`
     (deduplication) and a write that failed is retried once the path is
     writable (ported from gltui).
   - Isolation: the late rate-limited reply goes to the stage's own panel
     by calling its `receiveAction(...)` directly with a 429 reply (the
     global fake action keeps returning success, which the existing
     closed-rerun check expects); the stage's panel must not append to
     `notify-send.log` or `act.log`, whose exact contents the runner
     checks (set its `noticeBusy` or give it its own command); helper
     processes use `python3 -c`, not `sh`, because the `managed` scenario's
     `PATH` has only the fake bin directory. The teardown check first puts
     the stage panel in a non-`none` state, then destroys it and waits for
     `none`.
   - Verify: `python3 -c "import ast; ast.parse(open('tests/qml-smoke.py').read())"`;
     CI runs it.
   - Traps: never run it locally. Asynchronous checks must wait (return
     false) until ready and only throw after their deadline; the runner
     fails on any `ERROR:`, `CHECK FAILED`, `TypeError`,
     `ReferenceError` or `binding loop` line and needs the success marker;
     keep within the existing scenario deadline.
     FileView caches text: reload before reading.

7. **Docs and version** — `README.md`, `manifest.json`,
   `bar-widget/manifest.json`. Decision 11 and the spec's README list
   (what it shows, units, freshness, states; install by Git link
   `~/.config/omarchy/plugins/olafkfreund.github-actions-bar` and
   `omarchy bar put olafkfreund.github-actions-bar`, or the `bar` package;
   nixarchy as a follow-up; limits: counts are stale while closed except
   watches, failed covers only runs the panel has seen, an account switch
   while closed is seen at the next open; removal). Keep the README's
   local smoke commands as they are (they run headless), but do not run
   them on the desktop.
   - Verify: the lead reads the diff; `nix flake check -L`.

## Deviations

- Decision 4, from the Opus diff review: the `rate` fallback also requires
  `previous.account` to equal the current payload's account, so a failed
  reset write can never show an old account's counts under a new login
  (`tests/model.cjs`).
- Step 6, from the Codex and agy diff reviews: the widget smoke seeds
  `repo.last`, asks `Polling.next` on `p.polling` (`adopt()` makes a
  shallow copy), and clears the cooldown before its failed-save stage;
  a failed check exits the shell and a hang prints its output.
