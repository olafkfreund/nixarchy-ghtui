## Approved decisions

**Scope.** The panel gets its first write path: rerun all jobs, rerun failed jobs and cancel, on a selected run. Nothing else writes. Dispatch, approving deployments, force-cancel, debug-logging reruns and per-job reruns are out. There is no setting to turn writes off; a read-only token is the way to stay read-only. `menu.py`, `manifest.json` and `flake.nix` do not change (no new runtime file or tool; new tests go into existing files that `flake.nix` lines 76-77 already run).

**Keys.** One key per action, no action menu. They are free today (taken: `r R o / j k h l`; `ActionsPanel.qml` lines 234-253).

| Key | Action id | Offered when the selected row is |
| --- | --- | --- |
| `a` | `rerun` | a run row whose raw run has `status === "completed"` |
| `f` | `rerun-failed` | a completed run with conclusion `failure`, `timed_out`, `startup_failure` or `cancelled` |
| `c` | `cancel` | a run row whose raw run has `status !== "completed"` |

- They are never offered on repo, job, step, "more" or message rows.
- Eligibility is read from the raw run, not the row. A row has `run` as an ID string and a `status` already mapped through `state()` (a failed run shows `failure`), and has no conclusion, run number or branch. Resolve the raw run with `Polling.runFor(polling, row.repo, row.run)`. If it is gone, the key does nothing.
- A key that is not offered does nothing except put a fixed reason on the status line, for example "Only a finished run can be rerun". It never opens a confirmation.
- #42 adds `y ? g G`, #44 adds log and watch keys, #43 adds a load-more key. None may take `a`, `f` or `c`. While a confirmation is open the confirmation handler runs first, so `y` means "confirm" there and "copy link" (#42) everywhere else.

**Confirmation.** One y/n for every action (no typed repository name), pinned to the target:
- Pressing an offered key stores `{action, repo, run, text, done}`: strings only, copied from the row and from `describe()`. It never stores a row key or index, so polling that rebuilds or reorders rows cannot change what `y` sends.
- While `confirm` is set, `Keys.onPressed` handles it first and swallows every key: `y` confirms, `n` or Escape cancels, all else does nothing. Enter is not a confirm key. Auto-repeat (`event.isAutoRepeat`) is ignored, so a held `y` cannot fire twice. Escape backs out of the confirmation only: it does not clear the filter or close the panel. `/` is swallowed too, so search editing cannot start while a confirmation is open.
- `close()` clears `confirm`.
- The confirmation text replaces the footer. The action, `y`/`n` and the repository come first and the descriptive tail last, because the footer elides on the right (`ActionsPanel.qml` line 378).

**Helper `actions.py`: a closed write list.** A second mode `act` next to `page`. One JSON argument: `{"action": "rerun"|"rerun-failed"|"cancel", "repo": "o/r", "run": "123", "requestId": n}`. The action picks a fixed path; text from the task never reaches the path.

| Action | Request |
| --- | --- |
| `rerun` | `POST repos/{repo}/actions/runs/{run}/rerun` |
| `rerun-failed` | `POST repos/{repo}/actions/runs/{run}/rerun-failed-jobs` |
| `cancel` | `POST repos/{repo}/actions/runs/{run}/cancel` |

- The argument list is exactly `["gh", "api", "--hostname", "github.com", "--include", "--method", "POST", endpoint]`. No `-f`, `-F` or `--input`, so there is no body and no `@file` reading. Host pinning stays.
- `write_endpoint(task)` does what `page_endpoint` does: `repo_name()`, a run-ID check (the one at lines 70-73, moved into a small shared helper), a positive `int` `requestId`, and the closed action table. Anything else raises `ValueError("Invalid action")` before `request` is called.
- The docstring (line 1) becomes "GitHub Actions data and a closed set of run actions".
- `write_action(task)` reuses `http_reply()` and the rate-limit header parsing of `read_page()` (lines 141-152). Lift that block into one function that both call. Do not fork it.
- Reply: `{requestId, action, httpStatus, ok, error, errorType, retryAt, remaining, resetAt, updated}`. `errorType`:

| Condition | errorType | Message |
| --- | --- | --- |
| 2xx (rerun 201, cancel 202) | none | none; the panel writes the success text |
| 429, `remaining == 0`, `retry-after`, "rate limit" or "secondary rate" in the body (the test at line 162, lifted so both modes share it) | `rate` | `GitHub rate limit` |
| 401, or "auth login" on stderr with empty stdout | `auth` | `Authenticate with gh auth login` |
| 403 or 404 | `refused` | `Needs Actions write on {repo}: ` + GitHub's message |
| 409, 422 and other 4xx | `refused` | `GitHub refused: ` + GitHub's message |
| `gh` missing (`FileNotFoundError`) | `setup` | `Install gh (GitHub CLI)` |
| Timeout, `gh` exit with no HTTP reply, unreadable reply, invalid JSON in a 2xx, 3xx, 5xx | `unknown` | `Outcome unknown; check GitHub before retrying` |

- GitHub's message goes through `plain()` (line 27) and is cut to 120 characters. If it is empty, drop the trailing `: `. The write mode never uses `permission`, so a refused write cannot send the repository to `blocked` in `Polling.complete()`.
- `unknown` is used whenever GitHub's answer was not read. A killed or timed-out `gh` does not prove nothing happened. The panel never retries an `unknown` write.
- `main()` accepts `act`. On error it echoes `requestId` like `page` mode (positive `int` only). In `act` mode a `ValueError` or `KeyError` before any request is `setup` (nothing was sent), and `TimeoutExpired` or `OSError` is `unknown` with the fixed `unknown` text. `page` mode output must not change.

**Panel model `ActionsModel.js`** (pure functions, tested in Node):
- `actionsFor(run)`: the raw run in; `["rerun","rerun-failed"]`, `["rerun"]`, `["cancel"]` or `[]` out.
- `unavailable(action, run)`: `""` when the action is offered, else a fixed reason ("Only a finished run can be rerun", "Rerun failed needs a failed run", "Only an unfinished run can be cancelled", "Select a run to rerun or cancel" for a missing run). Small helper so the QML stays thin.
- `describe(action, repo, run)`: the raw run in; `{confirm, done}` out.
  - confirm for rerun: `Rerun all jobs? y yes · n no — owner/repo #42 CI (main)`.
  - confirm for rerun-failed: `Rerun failed jobs? y yes · n no — owner/repo #42 CI (main)`.
  - confirm for cancel: `Cancel run? y yes · n no · cannot be undone — owner/repo #42 CI (main)`.
  - done: `Rerun requested: …`, `Rerun of failed jobs requested: …`, `Cancel requested: …`, followed by `owner/repo #42 CI (main)`. "Requested", not "started", because GitHub only accepted the request.
  - Name (`run.name || "Workflow"`) and branch are each cut to 30 characters (29 plus `…`), and control characters (`[\x00-\x1f\x7f-\x9f]`) become spaces. The part that must stay visible is first.
- `actionReply(stdout, code, requestId)`: like `reply()` (lines 2-6) but for writes. Non-empty stdout is returned unchanged. Empty stdout with code 127 gives `{requestId, ok:false, errorType:"setup", error:"python3 not found"}` (nothing was sent). Empty stdout with any other code gives `{requestId, ok:false, errorType:"unknown", error:"Outcome unknown; check GitHub before retrying"}`. `reply()` is left alone, because `setup` there stops polling.

**Panel `ActionsPanel.qml`:**
- State: `confirm` (null or the pinned target), `actionBusy`, `actionText`, `actionError` (bool), `actionId`, `actionInfo`, `actionStarted`.
- Local gates, no request: `now < polling.cooldown` is refused with `cooldownText + ". Try again then."`, and `actionBusy` is refused with `An action is already running`. Check at the keypress (before a confirmation opens) and again at confirm time. One write at a time.
- A second `Process { id: actionProc }` runs `["python3", helper, "act", JSON.stringify(task)]`. It does not use `requestProc`, `workerBusy` or `Polling.flight`:
  - `complete()` drops a reply after the panel closes (generation check, line 169). A write result must not be dropped.
  - `close()` kills `requestProc` (line 57). A write in flight is left to finish; the helper's 25 s limit still applies.
  - A failed start (Quickshell 0.3.1 emits only `running=false`, no `started`, no `exited`; see `requestProc` lines 200-202) is handled with its own `actionStarted` flag. A failed start means nothing was sent, so it reports `setup` "python3 not found".
- Reply handling: parse the reply and check `requestId === actionInfo.requestId` the way `receivePage()` does (lines 151-165). A reply with a wrong ID, or that does not parse, becomes `unknown`; the raw text (up to 300 characters) goes to `console.warn`, never to the panel.
- Result: `actionText` shows on the footer for 10 seconds (a `Timer`) or until the next action key. A failure uses `Color.urgent`. On success the text is the pinned `done`, plus ` · refresh waits until HH:MM` if a cooldown now holds the refetch back. Drawn as `Text.PlainText`.
- After success (panel open): `Polling.noteWrite()` then `Polling.touch()`, then `adopt()` and `pump()`.
- `status()` gains `action` (the `actionText`), `actionBusy` and `confirm` (target or null).

**Panel `Polling.js`:**
- `cool(s, reply, now)`: lift the cooldown block of `complete()` (lines 176-181, including its `if`) unchanged, and call it from `complete()`.
- `noteWrite(s, reply, now)`: calls `cool()` and nothing else. It does not touch `s.error`, `s.auth`, a repository's `blocked` or `error`, `s.tasks` or `s.starts`. Writes do not count toward `TIMING.perWindow` but respect and extend the cooldown.
- `touch(s, repo, run, now)`: `ensure(s,"run",repo,run,"interactive",now)`, then set `t.due = now` explicitly (`ensure()` keeps an existing task's `due`, line 19-26). If `s.flight && s.flight.key === t.key`, set `t.again = true`. Delete `repoFor(s,repo).summaryAt` so the next `next()` also seeds the summary.
- In `complete()`, the `run` branch (line 211): if `t.again`, clear it and set `t.due = now` instead of `delete s.tasks[t.key]`. The post-write lookup is then always a request made after the write.
- "At once" means due now, still subject to cooldown, `gap` and the fairness slots in `next()`. This is accepted.

**Docs.** README: Requirements (line 22) says a token that can write Actions (classic: `repo` scope; fine-grained: Actions read and write plus Metadata read); a read-only token still works for everything else. Intro (line 3) and Authentication (line 129) say the panel can now rerun and cancel. Keyboard table (lines 133-146) gains `a`, `f`, `c` and the confirmation keys. "Refresh and errors" gets two sentences: writes do not count toward the request ceiling, they respect a cooldown, and an unknown outcome is never retried. `keybindings.sh` (lines 5-24) gets three key lines and one confirmation line.

## Repo traps (apply to every step)

- **Argument arrays only.** Never build a shell string; QML `command` is a list and `gh` is called with a list. `repo` and `run` go through `repo_name()` and the run-ID check before reaching `gh`.
- **GitHub text is untrusted (#32).** Pass GitHub's message through `plain()` and cap it. Draw it as `Text.PlainText`.
- **github.com pinning.** `--hostname github.com` stays in every `gh api` call.
- **Fixed UI strings (#24).** Raw stderr, tracebacks and gh output never reach the panel. They go to `console.warn`. The only GitHub-derived text shown is the capped, `plain()`-ed refusal message.
- **Quickshell 0.3.1 `Process`.** A failed start emits only `running=false`. Gate the fallback on "never emitted `started`", never on timing. `exited` always precedes `running=false` on a normal exit.
- **`shownFields` (`ActionsModel.js` line 93).** The confirmation and result live in the footer, not in row data, so no new row field is added and `shownFields` stays as it is. If a step adds a row field the delegate reads, add it to `shownFields`.
- **#36 no-rerun rule.** Tests assert deterministically. Never wrap a smoke or unit test in a retry or rerun. If one fails, stop and find the cause.
- **ponytail.** The smallest correct change. No generic pass-through, no optimistic UI, no new files, no settings. Comment only the why.
- **nixarchy owns the menu.** `menu.py`, `menu.example.json` and `manifest.json` do not change.
- Do not rename `s.auth`. Do not add a second timer or poller.
- Builds, reviews and commits stay with the session, not a coder. One commit per step, tests in the same commit as their code or just before it.

## Rollback

- Before merge: do not merge the PR, or `git revert` the step commits (each step is self-contained with its tests). Steps 5-6 can be reverted without the others; do not revert step 6 without step 8, which calls `noteWrite` and `touch`.
- After merge: `git revert` the merge commit. There is no data, config or state migration, and the panel keeps no persisted state, so the old read-only behaviour returns at the next shell reload.
- A side effect already sent to GitHub (a rerun or cancel done during the manual checks) is not undone by reverting; use the throwaway repository for those checks.
