# Plan: Make the QML smoke test pass or fail deterministically

## Approved decisions

- **Background:** `tests/qml-smoke.py` failed 3 times in 16 on p620, always
  with `CHECK FAILED: timeout stage=1`. On razer `main` bef2cad passed
  50/50, 25 idle and 25 under 16 busy loops. The p620 status lines were not
  kept. `tests/test_actions.py` `test_cancellation_reaps_gh` failed once
  under heavy load on p620, because it gives the fake `gh` a 2 s budget to
  start.
- **Hypothesis 1 (a reply read empty or cut short, which stops polling) is
  refuted by the source,** pending one probe:
  - Qt 6.11.2 `QProcessPrivate::_q_processDied()` reads stdout and stderr
    before it emits `finished`.
  - Quickshell 0.3.1 `Process::onFinished` calls
    `StdioCollector::streamEnded` (which sets `text` and emits
    `streamFinished`) before it emits `exited`.
  - So `pageOutput.text` is complete inside `requestProc.onExited`. The
    only case that can still truncate is a grandchild that writes after
    its parent has exited, and `actions.py` never does that.
- **Probe:** one-off, on razer, not committed. A scratch `quickshell -p`
  directory in `/tmp` holds one `Process` with a `StdioCollector`, set up
  the same way as `requestProc`. It runs each variant 200 times, idle and
  then under 16 busy loops. In `onExited` it compares `text.length` with
  the byte count the helper announced on stderr.
  - A: 1 MiB of JSON in 4 KiB `os.write` chunks, then `os._exit(0)`
    straight away. Expected: 200/200 complete.
  - B: 200 KiB in one `sys.stdout.write`, then `flush()`, then
    `os._exit(0)`. Expected: 200/200 complete.
  - C, the positive control: `print` into block-buffered stdout, then
    `os._exit(0)` without flushing. Expected: truncated or empty.
  - D: a forked grandchild writes 0.3 s after the parent has exited.
    Expected: truncated.
- **Decision rule:**
  - **Refuted** (A and B complete, C and D not): follow the refuted path,
    steps 3–6.
  - **Confirmed** (A or B lose data): follow the confirmed path instead
    (step 3′). `ActionsPanel.qml` handles a reply only after both
    `requestProc.exited` and `pageOutput.streamFinished` have fired, and
    keeps the exit code in a property. The fake helper from step 4
    (variant A shape) is the test that fails before the fix. Steps 4–6
    still apply.
  - **Ambiguous** (C or D do not show loss, so the probe can't detect it):
    stop, record the result on #36, and ask. Don't guess.
- **Self-describing smoke failures** (`tests/qml-smoke.py`):
  - In the 250 ms stage timer, before the stage branches:
    `if (panel.polling.auth) check(false, "polling stopped: " + panel.error)`.
  - The 18 s timeout message names each stage-1 condition that is still
    false (`requests>=6`, `jobs one/repo:7`, `catalogueComplete`) and still
    includes `panel.status()`.
  - The 18 s and 25 s budgets stay as they are.
- **Padding:** the fake `actions.py` adds a `"padding"` field of about
  200 KiB to every reply. It writes the reply in 4 KiB chunks with
  `os.write(1, …)`, then calls `os._exit(0)`. `Polling.complete` ignores
  the field.
- **Cancellation readiness:** the fake `gh` writes `pid.tmp` and then calls
  `os.replace` to rename it to `pid`. The test waits until `pid` exists or
  `actions.py` has exited. If `actions.py` exited first, the test fails
  with "actions.py exited before starting gh". The only time limit is a
  30 s hang guard, matching the fake's `sleep(30)`. The `SIGTERM`,
  `wait(timeout=3)` and reaped-child assertions stay as they are.
- **Reruns:** none, anywhere. `plan/2026-09-24-31-dead-code.md` is a record
  of merged work, so its history is not rewritten. One line is added right
  after its rerun paragraph ("A single failure is therefore re-run…"):
  `Superseded by #36: no reruns.`
- **Hosts:**
  - p620 runs nothing desktop-related, only the Python unit tests, the
    Node tests and `nix flake check`.
  - Every razer run is done by the agent from a `/tmp` clone. It uses the
    agent-bus protocol: `read_new` on `#agents` immediately before
    claiming, then post `CLAIM razer: <what>, ~<minutes>`, and afterwards
    `done razer: <result>`.
  - No shell restarts, and no changes to
    `~/.config/omarchy/plugins/olafkfreund.github-actions`.
  - The whole environment of razer's running `quickshell` is imported, not
    a hand-picked subset.

## razer command shape

Every razer step uses this shape, which imports the whole `quickshell`
environment:

```sh
ssh razer 'rm -rf /tmp/actions-36 && git clone -q --branch test/36-smoke-flake https://github.com/olafkfreund/nixarchy-ghtui /tmp/actions-36'
ssh razer 'pid=$(pgrep -u "$USER" -x quickshell | head -1)
  while IFS= read -r -d "" kv; do export "$kv"; done < /proc/$pid/environ
  cd /tmp/actions-36 && for i in $(seq 20); do /usr/bin/env time -f "%e s" python3 tests/qml-smoke.py >/tmp/actions-36/run-$i.log 2>&1; echo "$i $? $(tail -1 /tmp/actions-36/run-$i.log)"; done'
ssh razer 'rm -rf /tmp/actions-36'
```

If `/usr/bin/env time` is missing, use the shell's `time` builtin. Don't
install anything.
