## Approved decisions (copied from the spec)

Owner decisions: (1) logs open in a terminal through Omarchy's launcher `omarchy-launch-tui`; (2) a notification arrives with the panel closed (bends README "no polling while closed" and "no background daemon", made opt-in, per run, capped, visible); (3) shown with `notify-send`; (5) a failed job shows its failed steps only, any other completed job shows the full log; (6) the user marks a run, watching ends when it completes; (7) notification says repository, workflow and result; (8) only marked runs; (9) new runtime deps `less`, `libnotify` go in `flake.nix` `passthru.runtimeDeps` and the README, `omarchy-launch-tui` is named but not packaged (like `omarchy-shell`); (10) logs first.

Rules that stay: argument arrays, never shell strings; host pinned to github.com; no token storage; read-only; fixed UI strings; keyboard-first; the panel draws nothing new except one `watching` marker and a `· N watched` header suffix. New keys `v` (view log) and `w` (watch); #42 takes `y ? g G`, #45 must avoid `v` and `w`.

**Which log, for which row** ("failed" = `failure`, `timed_out`, `startup_failure`, the set `icon()` uses at `ActionsModel.js:19`):

| Row | Result |
| --- | --- |
| Job or step, job failed | `{mode:"failed"}` for that job |
| Job or step, job completed, not failed (a cancelled job is `full`) | `{mode:"full"}` for that job |
| Job or step, job not completed | `{error:"Logs are available when the job finishes"}` |
| Run, run completed and failed | `{mode:"failed"}`, no job |
| Run, anything else | `{error:"Select a job to read its log"}` |
| Repository, more, message rows | `null`: `v` does nothing |

A step row uses its job's rule and opens the whole job log (no per-step slicing).

**Helper `actions.py log '<json>'`:** request `{requestId, repo, run, job?, mode}`. Validate with `repo_name` (`actions.py:19`), run and job as positive integer strings (as `page_endpoint` lines 70-73), `mode` in `failed|full`; `job` may be absent only with `mode:"failed"`; `full` needs a job. Command, one array: `["gh","run","view"] + (["--job",job] if job else [run]) + ["--log-failed" | "--log", "-R", "github.com/"+repo]`. Read stdout in 64 KiB chunks, keep the last 1 MiB, keep draining after that; read stderr concurrently; hard timeout 90 s, kill and reap `gh` as `request()` does (`actions.py:52-55`). Clean the text: UTF-8 with replacement; remove ANSI CSI, OSC (`BEL` or `ESC \`) and lone `ESC`+1 char; drop `\r`; per line drop `Cc`/`Cf` except `JOINERS` (`actions.py:16`), keep `\n` and `\t`; cut lines over 2,000 characters and end them with `…`. Write a header (repo, run, job, mode, and `complete` | `cut short: showing the last 1 MiB of N MiB` | `lines cut: N lines longer than 2,000 characters were shortened`, both cuts possible, `complete` only when neither) using only validated values, then the text, with `tempfile.mkstemp` in `$XDG_RUNTIME_DIR/nixarchy-ghtui/` (dir `0700`, file `0600`). Empty cleaned output: no file. Reply is the existing JSON shape plus `data:{path, mode, cutShort, lineCut}`. Error mapping from stderr, checked in this order: `rate limit` / `HTTP 429` / `secondary rate` -> `rate`; `auth login` -> `auth`; `HTTP 401` -> `auth`; `HTTP 403` / `HTTP 404` -> `permission`; `FileNotFoundError` -> `setup`; else `network`. Raw stderr never reaches the reply. Each `log` call also deletes regular files in that directory older than one day.

**`actions.py view <path>`:** the path must be a regular file (not a symlink, not a directory) directly inside the runtime log directory; run `less -- <path>`, delete the file in a `finally`; anything else exits non-zero. The terminal command carries no GitHub text.

**Scheduler (`log` task kind):** `Polling.requestLog(s, target, now)` calls `ensure(s,"log",repo,run,"interactive",now)` and sets `t.job`, `t.mode`; `t.run` stays the plain run id. One `log` task at a time. `next()` adds `job` and `mode` to the request. A `log` start is charged four slots and the next start of any kind waits four gaps. A `log` error is final: `s.log={error}`, task deleted, no retry, and a `permission` error never sets `r.blocked`; `rate` still sets the cooldown, `auth`/`setup` still set `s.auth`. Success sets `s.log={path,mode,cutShort,lineCut,repo,run,job}`. `okData` accepts `log` like `run`. Owner call (2026-11-16): accept `gh run view`'s at least four back-to-back calls per log, charged as four slots; replace the factor with the figure measured in the live check.

**Watch:** `w` on an unfinished run toggles a watch, `w` on a finished run only says it finished; max 5 watches (the sixth is refused); a watch ends when the run completes, on un-watch, or on shell restart; nothing is written to disk; `keepLoaded` keeps the QML timers alive while closed. A watch is `{repo, run, name, at}` in `s.watches` keyed `repo:run`; `s.notices` is the output queue. One existing `run` task per watch, group `active` (`next()` only knows `interactive`, `active`, `background`), due `age(w.at, TIMING.watch)` with `TIMING.watch = 30000` (the spec's choice, not an owner decision), `w.at` stamped on creation and on every `run` reply. While closed `next()` considers only `run` tasks that belong to a watch, `seed()` creates only watch tasks, `complete()` accepts replies, and a `run` reply queues no `jobs` task. Completed run -> notice `{kind:"done",repo,name,conclusion}` and the watch is deleted. A re-run of the same id that is unfinished keeps the watch. `auth`/`setup` while closed -> one `{kind:"paused"}` notice, watches kept. `permission` on a watched run -> `{kind:"lost",repo,name}` and the watch is dropped. Network and rate errors use the existing backoff. `close()` does not clear `watches`. Closed-panel cost is at most `2 x watched` = 10 requests a minute. Notification text: `Model.notice(n)` returns `{title, body}`; done: title is the result word, body `<owner/repo> · <workflow>`; paused: "Watching paused" / "Run gh auth login, then open the panel"; lost: "Watch stopped" / `<owner/repo> · <workflow>` + " GitHub no longer shows this run."; result words: success "succeeded", failure "failed", cancelled "cancelled", timed_out "timed out", startup_failure "failed to start", skipped "skipped", neutral/action_required/stale/anything else "finished"; `<`, `>`, `&` become a space and the name is cut to 80 characters. Launch: `["notify-send","--app-name","GitHub Actions","--",title,body]`.

## Shared traps (apply to every step)

- GitHub text (workflow names, log lines) goes through `plain()`-style cleaning (#32); logs get the per-line variant, never `plain()` itself (it joins lines).

- `shownFields` (`ActionsModel.js:93`) lists the fields the delegate reads. `job` is not read by the delegate, so it is not added. `watching` goes inside `info`, which is already listed.
- #36: no reruns anywhere. A test must pass on its first run. Use injected `now`, shortened timeouts via a parameter, and rename-signalled fakes; a flaky test is fixed, never re-run. `nix flake check` runs the Python and Node tests only; the QML smoke test is local.
- Ponytail: smallest correct change, no new files except none (no new files are added), no new settings. nixarchy owns the menu: `menu.py`, `menu.example.json` and the registered menu entry are not touched.
