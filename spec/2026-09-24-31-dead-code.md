# Spec: Remove the panel's dead code and duplicated logic

## Design

### Baseline

This spec is written against `main` after PRs #26, #27 and #28 merge, in any
order. Line numbers are from `main` (4f51f7f) with those three diffs applied.
All three apply cleanly. After the merge, actions.py has 309 lines,
Polling.js 232, ActionsPanel.qml 406 and tests/test_actions.py 198.
Implementation waits for the merges and rebases onto them. If the merged
line numbers differ, the plan updates them.

The change only removes and consolidates code. The panel sends the same
requests at the same times and gets the same replies, including `errorType`
and `requestId`.

### actions.py: only page mode

- Delete `DeadlineExceeded` (16–18) and `api()` (42–54). Also delete
  `pages()`, `runs()`, `repositories_page()`, `activity()` and `summary()`
  (198–253). Nothing in page mode calls them. `read_page()` keeps its own
  projection and error classification. Keep `ACTIVE`: `page_endpoint()` uses
  it.
- `main()` (255–305):
  - `choices=("page",)`. Keep the positional `mode`, so the panel's
    `python3 actions.py page '<json>'` doesn't change. `summary`, `jobs`,
    `repositories` and `activity` now get argparse's usage error (exit 2)
    and no longer print a JSON error.
  - Delete the `# Bound the complete request…` comment, `timed_out`,
    `signal.signal(signal.SIGALRM, …)`, `signal.alarm(90)` and the
    `finally: signal.alarm(0)`. `request()` (28–39) already limits the one
    `gh` call with `communicate(timeout=25)` and kills the child. Keep
    `cancelled` and the `SIGTERM` handler.
  - Delete the four old-mode branches (277–291). The page branch becomes the
    body of the `try`.
  - In the `except`, drop `DeadlineExceeded` from the caught types and from
    #28's `errorType` test (298). That line becomes
    `"network" if isinstance(exc, (subprocess.TimeoutExpired, OSError)) else "setup"`.
    Drop the `if args.mode == "page":` guard (297), because page is the only
    mode. Every other `error`, `errorType` and `requestId` stays as #28 left
    it.

The file drops from 309 lines to about 212, removing about 97.

### tests/test_actions.py

- Delete the six tests of removed functions: `test_pagination`,
  `test_repository_discovery_pages_and_affiliations`,
  `test_activity_uses_paginated_running_filter`,
  `test_active_runs_and_completion_race`,
  `test_partial_failure_preserves_other_repos` and
  `test_deadline_stops_entire_scan` (17–56).
- Delete #28's `test_old_mode_error_unchanged` (187–188). It guards the
  `jobs` mode that this change removes.
- Rewrite `test_cancellation_reaps_gh` (63–84) to use page mode. The only
  change is the argv on line 69:
  `"page", '{"kind":"catalogue","requestId":1}'` in place of
  `"summary", "owner/repo"`. What it checks doesn't change: `SIGTERM`
  reaps the `gh` child.
- Delete `test_missing_gh_is_json_error` (86–90). The coordinator asked for
  both summary-mode tests to be rewritten, but #28's
  `test_page_missing_gh_end_to_end` (164–169) is already this test in page
  mode, and rewriting it would give a duplicate.

The file drops by about 48 lines. It then contains the page-mode tests only.

### Polling.js

- **Named timings.** Add one block at the top of the file:

  ```js
  var TIMING = {settle:250, catalogue:300000, summary:60000, selected:10000, active:15000,
      idle:600000, followup:15000, jobs:5000, window:60000, perWindow:60, gap:1000,
      rateBase:60000, rateMax:900000, retryBase:5000, retryMax:300000};
  ```

  The literals at 27, 34, 66, 71, 83, 90, 96–97, 165 and 180 use it. The
  values are the same, so `tests/polling.cjs` passes unchanged. Keep the
  `10` in the sort-and-trim, which is a row count, not a time, and keep
  `phases`.
- **One sort-and-trim.** `mergeRuns()` (136–138) and the end of a summary in
  `complete()` (222–224) run the same code: sort running first, then newest
  id first, then keep ten completed runs plus any expanded ones. Move it into
  `function recent(s, r, runs)`, which returns the sorted, trimmed list. Both
  places become `r.runs=recent(s,r,union(…))`.
- **`r.history`.** Delete `r.history=true;` (225). Nothing reads it.

### ActionsPanel.qml

- **`property var manifest`** (14): delete it. omarchy-shell sets `manifest`
  only `if ("manifest" in target)` (shell.qml:222), so a panel without the
  property gets nothing assigned and no warning. The coordinator checked
  this.
- **The `payload` parameter:** `function open(payload)` (46) becomes
  `function open()`. omarchy-shell calls `loader.item.open(queue[i])`
  (shell.qml:1263). JavaScript ignores the extra argument. `toggle()` (62)
  calls `open()`.
- **`repositories`**: delete the property (17) and its assignment in
  `adopt()` (137). The header (281) and the status line (314) use
  `repos.length`. `status()` (64) keeps its `repositories:` JSON key, now
  with the value `repos.length`, so anything reading `status()` gets the
  same output.
- **`loading`** (32): delete it. The panel reads `workerBusy`.
- **The `repositories` key in shell.json:** delete `configure()` (121–130)
  and the `FileView` for `~/.config/omarchy/shell.json` (203–209). Nothing
  else in the panel reads shell.json. If a user has
  `plugins[].repositories` set, it's ignored without any message. Their list
  used to appear only until discovery pruned it, so the only difference is
  that names show up at discovery speed. The key never limited discovery.
  Removing the `FileView` also removes the `Configuration: …` error for a
  malformed shell.json. That error only ever reported problems with the
  removed key.

### tests/qml-smoke.py

- Replace `panel.configure(…)` (84) with
  `panel.polling.repos=[{repo:"one/repo"},{repo:"two/repo"}]; panel.adopt()`.
  The `"configured repositories"` check then tests the same two rows. Rename
  it `"seeded repositories"`.
- Replace `panel.loading` (127, 134) with `panel.workerBusy`.
- Change `panel.open("{}")` calls to `panel.open()`. The old form would
  still work; this is only for consistency.

### README.md

- Delete the sentence "Legacy `repositories` settings are startup hints
  only and do not limit discovery." (125).
- In "Refresh and errors" (150–168), replace each number that comes from
  Polling.js with the name of its `TIMING` field, in backticks. For example,
  the table becomes `| Selected repository activity | TIMING.selected |`.
  Add one line saying the values live at the top of `Polling.js`. The
  25-second request timeout stays: it belongs to `actions.py`, not
  Polling.js. The measured comparison (170–179) also stays, because those
  are simulation results, not settings.

### Out of scope

- The legacy menu-key migration in menu.py (64–81) and its tests stay
  unchanged. Tagging a release (`v0.4.0`, the version in manifest.json) is
  a separate step, which the lead proposes to the user. Nothing is tagged
  here.
- ActionsModel.js, menu.py and flake.nix don't change.

### Size

About 97 lines removed from actions.py, 48 from the tests and 20 from
ActionsPanel.qml (`configure`, `FileView` and four properties). Polling.js
grows by about 3 lines net: the `TIMING` block is added and the second copy
of the sort-and-trim is removed. In total about 160 lines are removed.

## Alternatives rejected

- **Keep the old modes as a stub that points to `page`:** the user chose
  deletion, and argparse's usage error already names the one valid choice.
- **Keep the 90-second `SIGALRM` as a backstop:** page mode makes one
  request, which the 25-second `communicate` timeout already limits. A
  second timer is code that no test can reach.
- **Rewrite `test_missing_gh_is_json_error` to use page mode:** it would
  duplicate #28's `test_page_missing_gh_end_to_end`.
- **Keep or document the `repositories` key:** the user chose removal.
  Discovery prunes its entries anyway.
- **Make `repositories` pin repositories:** that's new behaviour and would
  need its own issue.
- **Keep the README numbers and add a test comparing them with `TIMING`:**
  the user chose naming the constants. A test that parses README prose
  would break easily.
- **Share the timings with actions.py or a JSON file:** only Polling.js
  uses them. A shared file would be a new abstraction with one consumer.
- **Remove the menu migration now:** no release has been tagged, so users
  may still have the old keys. It's kept until a release is tagged.

## Risks

- **The PRs merge differently.** If #26, #27 or #28 change before they
  merge, the line numbers move. The plan confirms them after the rebase.
  If #28 no longer adds `test_page_missing_gh_end_to_end`, the missing-`gh`
  test is rewritten to page mode instead of deleted.
- **External scripts.** Anyone who runs `actions.py summary`, `jobs`,
  `repositories` or `activity` gets a usage error on stderr, exit 2, and no
  JSON. None of these are documented. The panel calls only `page`.
- **A hang outside `request()`.** Without `SIGALRM`, a hang in page mode
  would never time out. The only blocking call is `communicate(timeout=25)`,
  and JSON parsing of the reply is bounded by its size. Closing the panel
  still sends `SIGTERM`.
- **Configured `repositories`.** Users who set the key see no warning, and
  the list starts empty until the first catalogue page arrives. That page
  is the first request, which is only noticeable on a slow network.
- **Constants refactor.** A mistyped `TIMING` field is `undefined`. That
  gives `NaN` deadlines, and the task never becomes due. `tests/polling.cjs`
  checks the request counts, data ages and limits, so it would catch this.
- **omarchy-shell.** Removing `manifest` relies on the `"manifest" in target`
  guard at shell.qml:222. If a future shell drops that guard, it will log an
  assignment warning, not break the panel.

## Verification

- `python3 -m unittest discover -s tests -v`: all pass. The cancellation
  test passes in page mode, and no remaining test uses `summary`, `jobs`,
  `repositories`, `activity` or `DeadlineExceeded`.
- `node tests/model.cjs` and `node tests/polling.cjs` both exit 0.
  `polling.cjs` prints the same request counts and data ages as before the
  change.
- `tests/qml-smoke.py`, where a display is available, prints
  `QML_CHECKS_PASSED`.
- `nix flake check` passes.
- `python3 actions.py summary a/b` exits 2 with argparse usage.
  `python3 actions.py page '{"kind":"url","requestId":7}'` prints the same
  JSON as before.
- The following greps return nothing:
  - `grep -n "DeadlineExceeded\|SIGALRM\|def api\|def pages\|def runs\|def summary\|def activity\|repositories_page" actions.py tests/test_actions.py`
  - `grep -n "history\|300000\|600000\|60000\|15000\|10000\|5000" Polling.js`
    (matches only inside the `TIMING` block are allowed)
  - `grep -n "manifest\|loading\|configure\|shell.json\|root.repositories" ActionsPanel.qml`
- On razer, open the panel, drill into a running run and close it. It
  behaves as before, and `status()` reports the same keys.
