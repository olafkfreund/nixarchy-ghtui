# Spec: A bar indicator for running and failed workflow runs

## Design

The sister plugin's shipped design (nixarchy-gltui #41, its
`bar-widget/`, `PipelinesModel.js` `barCounts`/`barStatus` and
`PipelinesPanel.qml` `publishStatus`), ported by hand to one GitHub
account and without `shell.json` settings. Approved intent decisions: a
separate widget plugin fed by a status file; "failed" is the panel's own
failing rows; no polling while closed beyond watches; left click only;
nixarchy does not place the widget.

```mermaid
flowchart LR
  P[ActionsPanel adopt()] -->|Model.barStatus| F[(status file)]
  F -->|FileView watch| W[bar widget, one per screen]
  W -->|left click: omarchy-shell shell toggle| P
```

### The widget plugin (`bar-widget/`)

- **`manifest.json`**: `schemaVersion: 1`, id
  `olafkfreund.github-actions-bar`, name "GitHub Actions bar", `version`
  equal to the panel's, `author`, `description`; `"kinds":
  ["bar-widget"]`, `"entryPoints": {"barWidget": "BarWidget.qml"}`;
  `barWidget`: `displayName` "GitHub Actions", `category` "Development",
  `allowMultiple: false`, `defaultSection: "right"`. No `keepLoaded`.
- **`BarWidget.qml`**: a `qs.Ui` `BarWidget` holding one `Ui.WidgetButton`
  that fills it (the whole widget is the click and tooltip target), with
  `pressFeedbackButtons: Qt.LeftButton`. `text`, `active`, `dimmed`,
  `tooltipText` and `Accessible.name` come from `BarModel.view`; on a
  vertical bar the label's parts are joined with `"\n"`. A left press runs
  `Quickshell.execDetached(["omarchy-shell", "shell", "toggle",
  "olafkfreund.github-actions", "{}"])`; other buttons do nothing. A
  `FileView` on the status path (`watchChanges`, `printErrors: false`)
  passes `text()` to the model on load and `""` on a failed load,
  reloads on change, and shows `none` when `statusPath` changes
  (`onStatusPathChanged`). A one-shot `Timer` re-evaluates at
  `recheckAt` (interval clamped to 100 ms … 24 h). All text is plain.
- **`BarModel.js`**: pure `view(text, now, vertical)` → `{state, label,
  tooltip, accessible, active, dimmed, recheckAt}`. Empty, unparseable,
  `version !== 1` text, or a `state` outside `none`/`ok`/`stopped`/`rate`
  → `none`. `active` (urgent) is `state === "stopped" || failed > 0`, in
  every state including `rate`; `dimmed` is `state === "none" || state
  === "rate"`. Counts are clamped to non-negative
  integers; `account` is used only if it is a string, cut to 100
  characters; `reason` likewise, cut to 120. A `rate` whose
  `cooldownUntil` has passed becomes `ok` if `countsAt > 0`, else `none`.
  The GitHub glyph U+F09B is written in the source as the escape `\uF09B`.
- **`LICENSE`**: a copy of the root licence.

### The status file

- **Path:** `$XDG_RUNTIME_DIR/omarchy-github-actions-<WAYLAND_DISPLAY>.json`,
  computed on both sides from `Quickshell.env` and exposed as a property
  tests can override; `""` (write nothing, show `none`) if either variable
  is empty. The runtime directory is private, emptied at logout, and the
  display name keeps two sessions apart.
- **Shape**, written whole by a `FileView` (`atomicWrites: true`,
  `blockWrites: true`, `printErrors: false`) with `setText`:

  ```json
  {"version":1,"instance":"<random>","account":"octocat","state":"ok",
   "running":2,"failed":1,"countsAt":1795113908000,"cooldownUntil":0,
   "reason":"","writtenAt":1795113909000}
  ```

  `state` is `none`, `ok`, `stopped` or `rate`. `account` is the verified
  `gh` login or `""` (unverified). The only other free text is `reason`,
  the panel's own error string.

### The panel side

- **`Model.barCounts(repos, now)`** in `ActionsModel.js` → `{running,
  failed}`. It skips archived, disabled, blocked and errored repositories.
  `running` sums the per-repository number the rows show (`repo.active`,
  or the cached `in_progress` runs when unset). `failed` counts
  repositories whose `Model.health(repo, now, 0).status === "failure"`,
  i.e. `r.last.conclusion` is in `FAILED` — the same rule as the rows.
- **`Model.barStatus(polling, instance, now)`** → the object above; the
  first matching rule wins:
  1. `stopped`, with `reason` = `polling.error` when `polling.auth`
     (sign-in or setup stop), else `polling.catalogueBlocked` when set;
  2. `rate`, with `cooldownUntil = polling.cooldown`, when in the future;
  3. `none`, when `polling.countsAt === undefined`;
  4. `ok`.

  Counts and `countsAt` are carried in every state, except that in `rate`
  the panel keeps the counts and `countsAt` of its last published non-rate
  status (`barStatus(polling, instance, now, previous)`, `previous` being
  the last published payload): a rate-limited reply marks its repository
  errored, and the paused widget must keep showing the last counts, not
  drop that repository. `account` is
  `polling.accountVerified && polling.account ? polling.account : ""`.
  Transient request errors are never read. The quota slowdown is not a
  state.
- **`Polling.countsAt`**: a new field in `create()`, starting
  `undefined` (a timestamp of 0 is a valid set value in tests). `activity()` sets it
  to `now` (summaries call `activity()` for their in-progress phase). A
  completed catalogue with no pollable repository sets it too, so an
  empty account shows `ok` with zero counts. Run, jobs, log, account and
  load-more replies never set it. The account reset in `complete()`
  (a different verified login) deletes it with the repositories.
- **Publishing** (`ActionsPanel.qml`): new `statusPath`,
  `statusInstance` (set once at `Component.onCompleted`), `lastStatus`,
  `pendingStatus`, a `FileView` writer and `publishStatus()`.
  `publishStatus()` serialises `barStatus` without `writtenAt` and writes
  only when it differs from the last successful write (recorded in
  `onSaved`; a failed save stays unrecorded so the next call retries; a
  `statusPath` change clears both). It runs:
  - in `adopt()` before its `if (!opened) return`, so replies while
    closed (watches) publish too;
  - after `Polling.noteWrite` in `receiveAction`, so a cooldown from a
    rerun or cancel that returns after close is published;
  - in `ActionsPanel.open()` after `Polling.open()` and in `refresh()`
    after `Polling.manual()`, which clear a stop (and, on open, the
    verified login) without a reply, so the widget never keeps an old
    stop reason or login;
  - at `Component.onCompleted`, writing `state: none` with the new
    instance;
  - at `Component.onDestruction`, best effort, writing `none`.
- The watch running-count rule is already in place (ghtui #60): a counted
  run that finishes decrements an API total, and a closed watch reply
  updates `r.active` and `r.last` without touching `countsAt`.

### The widget's states

| State | Label | Colour | Tooltip |
| --- | --- | --- | --- |
| `none` | glyph | dimmed | "Open GitHub Actions to load" |
| `ok` | glyph, `●N` if running > 0, `✕N` if failed > 0 | urgent if failed > 0 | "GitHub Actions · <account>" (or "GitHub Actions"), "N running workflow runs, N failing repositories", "Last repository activity read at HH:MM; watched runs are checked every 30 s, slower when the quota is low" |
| `stopped` | glyph and `!` | urgent | "GitHub Actions stopped" + (": <reason>" if any) + ". Open the panel to fix it." |
| `rate` | glyph and the last counts | dimmed, and urgent if failed > 0 | "GitHub paused until HH:MM", then the `ok` lines when `countsAt > 0` |

Units are singular or plural as needed; the accessible name is the
tooltip lines joined with ", "; `HH:MM` is zero-padded local time.

### Packaging and docs

- **`flake.nix`**: a second package `packages.<system>.bar` copies
  `bar-widget/`; `packages.default` stays the panel. `checks.plugin` also
  checks the `bar` package (file list, no symlinks, manifest id, kinds,
  entry point, version equal to the panel's) and runs `node
  tests/bar.cjs`.
- **`tests/qml-smoke.py`** (CI only) gains a widget stage with fake bar
  objects and a fake `omarchy-shell` on `PATH`, as gltui's. ghtui's
  harness uses local stubs (`tests/stubs/Ui`), so `BarWidget` and
  `WidgetButton` stubs are added there with the properties the widget
  uses (`bar`, `vertical`, `text`, `active`, `dimmed`, `tooltipText`,
  `pressFeedbackButtons`, the `pressed(button)` signal). The stage runs
  only when the source has `bar-widget/` (a `./result` package run skips
  it and says so); the main panel and the widget stage's panel use
  separate status paths.
- **README**: a "Bar widget" section (what it shows, units, freshness,
  states), install (Git link as
  `~/.config/omarchy/plugins/olafkfreund.github-actions-bar` then `omarchy
  bar put olafkfreund.github-actions-bar`; Nix: the `bar` package;
  nixarchy: a follow-up), known limits (counts stale while closed except
  watches; failed covers only runs the panel has seen; an account switch
  while closed is seen at the next open), and removal.
- **`manifest.json`**: version 1.2.0 (a new feature after 1.1.1).

## Alternatives rejected

- **A `bar-widget` kind on the panel plugin**: changes how the panel is
  enabled and listed.
- **The widget polling GitHub itself**: extra requests against a quota
  shared with every `gh` tool, and a second login check.
- **Counting failed runs on any branch**: pull-request branches would
  make the indicator noisy; the rows already use the default branch.
- **The state directory for the file**: may not exist, QML cannot create
  it, and it keeps a stale status across reboots.

## Risks

- **Stale counts while closed** are the accepted trade-off; the tooltip
  gives their time.
- **Two shells on one Wayland display** would share the file (as gltui).
- **A write still in flight** when `statusPath` changes: `blockWrites`
  makes writes synchronous, as gltui's fix.
- Hosts: p620 and razer after release; p510 untouched.

## Verification

- `node tests/bar.cjs` (new): every state, the unknown-state guard,
  clamping, string checks, empty reason, `active`/`dimmed` in `rate` with
  failures, expired rate, vertical label, plural units.
- `node tests/model.cjs`: `barCounts` skips archived, disabled, blocked
  and errored repositories and counts the three failure conclusions;
  `barStatus` precedence (auth, catalogue block, rate, none, ok), the
  unverified account, and `rate` keeping the previous counts after a
  rate-limited repository reply.
- `node tests/polling.cjs`: `countsAt` set by activity and by an empty
  completed catalogue, not by run/jobs/log/account replies, and cleared
  by a different verified login; a closed watch finishing updates counts
  without moving `countsAt`.
- `nix flake check -L` (with the `bar` package checks).
- CI `qml-smoke`: the widget reads a status file, shows each state and
  `none` for an unknown state or a deleted file, two widgets show the
  same, a left click runs the toggle once and other buttons do nothing,
  the panel writes `none` at start and on destruction, a closed watch
  that finishes changes the counts in the file without moving
  `countsAt`, a late rate-limited action reply publishes `rate` while
  closed, and reopening clears a published stop.
