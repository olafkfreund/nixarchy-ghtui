# Spec: Panel UI tells you what is happening and reacts to the keys and mouse you expect

## Design

### Scope

This is a presentation change. It touches `ActionsPanel.qml`, `ActionsModel.js`, one small hook in `Polling.js` (quota), and the text cleaning in `actions.py`. It also touches `keybindings.sh`, `README.md`, `flake.nix` and the tests. It makes no new GitHub requests. `Polling` scheduling, the budget and the cooldown rules do not change.

It lands after #41 and before #43 (decision 12). Line numbers below are from `main` at 6d42838, checked in the current files.

### Owner decisions

These are binding. Each is restated with how the design meets it.

1. **Errors, pause end and quota get their own always-visible status line.** One new `Text` between the search field and the list (see "Status line").
2. **Run row shows branch · event · actor · age · title. No SHA or attempt.** See "Run rows".
3. **A click selects the row and toggles it, the same as Enter.** See "Keys and mouse".
4. **Right opens or enters a row. Left collapses or goes to the parent.** Enter and Space still toggle.
5. **Expansion state survives filtering.** The `expanded = ({})` reset at `ActionsPanel.qml:36` is removed.
6. **The search area shows how many repositories have run data loaded.** See "Search".
7. **Keys added: `y` copy link, `?` keys sheet, `g` / `G` top and bottom.** Not `q`, not Ctrl-d/u.
8. **`o` on a step opens that step only if GitHub's step anchor is verified stable. Otherwise it keeps opening the job.** I could not verify it, so the job link stays (see "Checked facts").
9. **If the theme has no success colour, rely on icon and label.** The theme has none (see "Checked facts"). Success becomes the plain text colour. It does not get a new colour.
10. **Stale or failed job data is shown under the run, and that work follows #41.** This spec only removes the fetch stamp from the subtitle. #41 owns the replacement.
11. **Accessibility: set the Qt accessibility properties and cover them in the QML smoke test.** No screen-reader session is part of this task.
12. **Order: after #41, before #43.**

### Checked facts

- **The theme has no success colour.** `$OMARCHY_PATH/shell/Commons/Color.qml` defines `foreground`, `background`, `accent`, `urgent` and `muted` (lines 19-23), plus the `menu.*` roles (lines 100-107). Decision 9 applies. This spec uses only `Color.accent`, `Color.urgent` and `Color.menu.text`, which the panel already uses. It adds no new theme names, so it also works with the stub `qs.Commons` that #47 plans.
- **Run fields.** I ran `gh api repos/olafkfreund/nixarchy-ghtui/actions/runs?per_page=1` on 2026-11-16. A run carries `event` (a string, "push" in my sample), `actor` (an object with `login`), `triggering_actor`, `created_at`, `run_started_at`, `updated_at`, `head_sha` and `run_attempt`. So everything decision 2 needs is already in the data the panel fetches.
- **Steps have no link.** A step has only `name`, `number`, `status`, `conclusion`, `started_at` and `completed_at`. Step numbers are not contiguous. My sample had 1, 2, 3, 4, 8 and 9, so anything keyed on a step must use `number`, not the index. Only the job has `html_url`.
- **Step anchor: not verified.** The job page for a public run returns 200, but the response (also with `#step:4:1` appended) holds no `step:N:L` markup. GitHub handles the anchor in the browser after it loads the log, so I cannot prove it from `gh`, `curl` or the REST docs. I remember the `#step:N:L` form from log line permalinks, but that is memory, not a check. Decision 8's fallback applies: step rows keep `url: job.html_url` (`ActionsModel.js:78`). If the owner confirms the anchor in a browser later, the change is one line: `job.html_url + "#step:" + step.number + ":1"`, still through `Model.browsable()`.
- **Copy command.** `wl-copy` exists on this host. Omarchy itself calls `wl-copy --sensitive -- <value>` in `shell/plugins/notifications/Service.qml.orig:1254`, so the `--` argument terminator is in use there. Other Omarchy panels run it through `bash -c` with shell quoting (`plugins/panels/network/Panel.qml:508`). The plugin must not copy that style, because it keeps "arguments, not shell strings".
- **Keys sheet command.** `menu.py:152` already runs the sheet as `["bash", <dir>/keybindings.sh]`. `keybindings.sh` calls `omarchy-shell shell hide`, then `omarchy-menu-select`. Both commands exist under `$OMARCHY_PATH/bin`. The `?` key reuses that command.
- **Quickshell is 0.3.2 here.** `ActionsPanel.qml:201` still says 0.3.1. The comment is stale. Its claim that a failed start emits neither `started` nor `exited` is the one the copy process relies on, so it is re-checked on razer (see Verification).

### Status line

A new `Text` sits between the search field and the hairline (after `ActionsPanel.qml:300`). It has a fixed one-line height, so the list does not jump. It is always shown. It carries four things, in this priority:

1. **A transient notice** from a panel action ("Copied link", "Install wl-clipboard to copy links"). It lasts 3 seconds, tracked with `now` (which already ticks every second). A notice is additive: it is put first and joined with the error and pause by " · ". It never replaces them, so decision 1 (always visible) holds while a notice shows.
2. **The error.** This is `polling.error`. When that is empty, it is the first repository's `r.error`, shown as `owner/name: message`. The fallback matters because `s.error` is cleared by any later success (`Polling.js:200`), so an unrelated reply can erase a failed repository's message while that repository is still failing. The repository's own error is kept separately (`Polling.js:188`, `:196`), so the line keeps showing it. Error text is urgent-coloured.
3. **The GitHub pause**, "GitHub paused until HH:MM:SS". It moves here from the placeholder (`:31`, `:292`) and the footer (`:374`). It is urgent-coloured and does not hide the error. Both are joined with " · ".
4. **Progress**, only when there is no error or pause. This is the current "Discovering repositories… N found" or "Activity checked N/M" text, moved out of the placeholder (`:293`).

The **quota** is right-aligned in the same line: "4,923 API requests left", dimmed. It is shown only while `now < resetAt`, because after the reset the old number is wrong. When fewer than 500 remain, it adds "· resets HH:MM". The value is the last one read from a reply. It is held in memory and not written anywhere.

A pure function `Model.statusLine(state, now)` builds the text parts and an `urgent` flag, so node can test it. The QML only draws it.

**Quota source.** `actions.py:142-145` already puts `remaining` and `resetAt` in every reply. In `Polling.complete()`, before the error branch (so a rate-limit reply with `remaining: 0` is kept), add: when `typeof reply.remaining === "number"`, set `s.quota = {remaining, resetAt}`. A reply without the header leaves the old value. #41 decision 4 slows polling as quota falls, so it needs the same number. #41 lands first, so if it has already added a field for this, reuse that field and add no second copy. The plan checks this.

**Footer.** The footer keeps only the key hint. It drops `root.cooldownText ||` (`:374`). The hint gains `y copy  ? keys`.

### Search

- **The placeholder is only a placeholder.** It is a fixed "Search repositories…" (`:292`). Nothing important lives in it, so typing can no longer hide anything.
- **A coverage note stays visible.** A small right-aligned `Text` inside the search row (not a placeholder, so it stays while typing) reads "recent runs loaded for N of M repositories". `searchField.rightPadding` is set to its width so typing does not run under it.
  - **N counts repositories with `summaryAt` set.** This is the full snapshot, finished runs included (`Polling.js:238`). I did not use "has a `runs` array". A repository gets `r.runs = []` as soon as the activity check merges an empty page, so that would count nearly every repository, and finished runs are still missing for most of them.
  - **The note is honest about the rest.** Other repositories can match only on their name, description and any running runs the background check found. This is a fixed, one-line note, not a per-repository list (decision 6).
- **Search matches the label as well as the raw state.** The haystack in `rows()` (`ActionsModel.js:41`) adds the plain label, so typing "failed" finds `failure` runs. The raw state stays in it, so existing searches keep working.
- **Expansion survives.** `onFilterTextChanged` (`:35-39`) no longer clears `expanded`. A repository you opened stays open while you type, if it still matches. A repository that stops matching leaves the list, and its expanded flag is kept for when the filter clears. This changes README line 123 ("Search results stay collapsed until you expand them").
- **The cursor keeps its place when the filter clears.** The same handler calls `rebuild(true)`, which jumps to the top. While typing, it should still jump to the first match. When the field becomes empty, it calls `rebuild(false)`, so the selected row stays selected (`Model.selection` already finds it by key).

### Empty and loading states

`ActionsPanel.qml:366` becomes `Model.emptyText(state)`. It returns the first match of:

| Condition | Text |
| --- | --- |
| No repositories, and an error is set (auth, setup, permission) | the error text |
| No repositories, discovery not finished | "Discovering repositories…" |
| No repositories, discovery finished | "No repositories found for this account" |
| A filter is set | `No match for "<filter>"`, then "search covers loaded runs only" |

The filter text is the user's own, but the label keeps `textFormat: Text.PlainText`.

**An expanded repository gets a message row.** In `rows()`, after the repository row and its "more" row (`ActionsModel.js:50-57`), when `repo.runs` has no entries and there is no "more" row:

- `summaryAt` set and no `repo.error`: a `message` row, "No workflow runs".
- `summaryAt` not set and no `repo.error`: a `message` row, "Loading runs…".
- `repo.error` set: no row. The repository's own subtitle already shows the error (`:47`).

This keeps "not loaded" and "no runs" apart, which `(repo.runs || [])` (`:40`) cannot. The row has kind `message`, which `expand()` and the delegate already ignore for toggling, and it carries `repo`, so selecting it selects its repository.

### Labels and colours

- **`Model.label(status)`** maps the raw state to a short plain word. It is a lookup table:

  | Raw | Label |
  | --- | --- |
  | `in_progress` | running |
  | `queued`, `requested`, `pending` | queued |
  | `waiting` | waiting |
  | `success` | passed |
  | `failure` | failed |
  | `timed_out` | timed out |
  | `startup_failure` | startup failed |
  | `cancelled` | cancelled |
  | `skipped` | skipped |
  | `neutral` | neutral |
  | `action_required` | needs action |
  | awaiting final status | checking result |
  | `unavailable` | unavailable |
  | anything else | unknown |

  **Anything not in the table shows "unknown".** `status` and `conclusion` are not cleaned by `actions.py`. Showing a raw, unmapped GitHub string would break the #32 rule, and the table is the safe way around it.
- **Rows get a new `statusText` field.** The delegate prints `modelData.statusText + (info ? " · " + info : "")` (replacing `:355`). `statusText` is added to `shownFields` (`ActionsModel.js:93`), so it repaints when it changes. `status` stays raw, because icons, colours and tests read it.
- **`statusColor()` (`:166-170`)** changes only the success case:
  - failure, timed out, startup failure, error: `Color.urgent`, as now.
  - running: `Color.accent`, as now.
  - everything else, including success: `Color.menu.text`.

  Success and running now differ in colour. Icon (✓ and ◷) and label also carry the meaning, per decision 9.

### Run rows

`rows()` builds the run subtitle as:

`branch · event · actor · age · title`

- **`age`** is `Model.age(run, now)`. It uses `run_started_at || created_at` and prints "now", "5m ago", "3h ago" or "2d ago". It changes once a minute, so `syncRows` repaints it rarely. It is only string work, so the 1 Hz rebuild stays cheap.
- **The job-fetch stamp (`:62`) is removed.** #41 decision 6 shows an expanded run that stopped refreshing, with its age, under the run. That is the replacement for the only thing the stamp told you. If #41 has not landed, this part waits.
- **`#run_number` is dropped.** Decision 2 lists the five fields and does not include it. I flag this in Risks.
- **Branch, event and actor are capped in the subtitle only, so the title keeps room.** The intent says the title must not be the first thing cut. The subtitle is one right-elided line (`:347`) with the title last, so without caps a long branch (dependabot branches are common), event or actor would push it off. The caps are branch 28, actor 16 and event 14 characters, each with an ellipsis. Full values are still searched. The caps are my call, since decision 2 fixes the field order and not the widths. The plan checks this visually at the narrowest panel width and records the result. If the title is still cut there, the owner decides what gives, because the field order is binding.
- **No SHA and no attempt**, as decided. The `Polling.js` uses of `run_attempt` (lines 90 and 128 in the old numbering) are unchanged.

### Helper: clean the new text (#32)

`actions.py:42` cleans `name`, `display_title` and `head_branch`. `event` and `actor` are not cleaned today and will be shown.

- Add `"event"` to `RUN_TEXT`.
- Flatten `actor` to its login string, cleaned: `row["actor"] = plain(actor.get("login") or "") if isinstance(actor, dict) else ""`. The object also carries avatar and API URLs, none of which the panel needs. A string is also what the model can print without reaching into an object.
- Put both in one small `clean_run(row)`, called where `plain_fields(..., RUN_TEXT)` is called now (`:182` for the `run` kind and `:192` for run lists). The `run` kind must use it too. `mergeRuns` would otherwise replace a string actor with an object, or the reverse, depending on which reply arrived last.
- `#46`'s detail pane reads "what the run already carries". After this change that is `actor` as a login string. #46 lands later and should read it as such.

### Keys and mouse

**Modifier guard.** At the top of `Keys.onPressed` (`:234`), before any key is matched, if Ctrl, Alt or Meta is held, set `event.accepted = false` and return. Shift stays allowed (`R`, `G`, `?`, Shift+O). This stops Ctrl+R (refresh), Ctrl+O (open) and Ctrl+J (move) from acting by accident. It is a behaviour change, and it is documented. With `WlrKeyboardFocus.Exclusive` (`:214`), an unaccepted key goes nowhere, so the gain is only that the panel no longer acts on shortcuts it does not list.

**Right and Left (decision 4).** A new `root.enter()`:
- on a collapsed row that can expand (`repo`, `run`, `job`): expand it.
- on an expanded row: move to its first child (`entries[cursor + 1]`, when that row's `parent` is this row).
- on any other row: do nothing.

Right and `l` call `enter()`. Left and `h` keep calling `expand(true)` (`:245`): collapse an open row, otherwise go to the parent (`:104-109`). Enter and Space keep calling `expand(false)`, the toggle (`:246`). The Enter handler inside the search field (`:278-280`) is unchanged.

**Paging.** `move(8)` and `move(-8)` (`:241-242`) become `root.page(±1)`. A screenful is `list.indexAt(1, list.contentY + list.height - 1) - list.indexAt(1, list.contentY)`, with a minimum of 1. `indexAt` is already used in `rebuild()` (`:70`). Row heights differ (`:314`), so a count of rows is the only unit that works. `indexAt` returns -1 when the point is below the last row, which happens on a short list or at the bottom of a long one. When the bottom lookup is -1, use the last index. When the top lookup is -1, use 0. This keeps Page Up and Page Down from degrading to one row.

**`g` and `G`.** They call `move(-entries.length)` and `move(entries.length)`, the same as Home and End (`:243-244`). They are matched on `event.text`, not `event.key`, because Shift state decides the case. `event.text` also makes `?` work on layouts where it is not Shift+/.

**`y`: copy the link.** A new `Process` (`copyProc`). While it is running, a second `y` is ignored and shows the notice "Copy in progress". The result notice belongs to the copy that started, not to the row selected when it finishes. With the command set per copy to `["wl-copy", "--", current.url]`. This runs only when `Model.browsable(current.url)`, the same gate as `o` (`:171-174`), so only a pinned github.com link is ever copied. It is an argument array and never a shell string.
- **Success:** the notice "Copied link".
- **Non-zero exit:** the notice "Copy failed (exit N)".
- **`wl-copy` missing:** the notice "Install wl-clipboard to copy links". It uses the same start-failure pattern as `requestProc` (`:200-202`), where a failed start emits only `running = false`.
- **A row with no link** (a message row, or the "more" row): the notice "Nothing to copy". A step has its job's link and copies it.
- **The new runtime dependency.** `pkgs.wl-clipboard` goes into `passthru.runtimeDeps` (`flake.nix:34-38`) and the package lists in `README.md` (`:23`, `:62` and `:67`).

**`?`: the keys sheet.** It runs the same command as the menu entry: `Quickshell.execDetached(["bash", <dir>/keybindings.sh])`. That script already hides the panel and opens the native key list. This is the cheapest way, with no second copy of the key list in QML, and it closes the panel the same way the menu entry does.

**Mouse (decision 3).** The delegate gets a `MouseArea { anchors.fill: parent }`. On click it sets `root.cursor = index`, calls `selectionChanged(false)`, gives focus back to the key handler (`keys.forceActiveFocus()`, so a click while searching ends editing), then calls `expand(false)`. Rows that cannot expand (step, message, "more") are not toggled, because `expand()` only toggles `repo`, `run` and `job` (`:110`). The click path still ends with the same `selectionChanged(true)` and `pump()` that `expand()` runs today, so a click on a step refreshes selection the same way Enter does. Wheel scrolling still comes from `ListView`. No hover effect is added, and no buttons.

`keybindings.sh` and the `README.md` key table (lines 134-146) list every key that works: Right/`l` open, Left/`h` close, `g`/`G`, `y`, `?`, the screenful paging, and the one-line note that Ctrl/Alt combinations are left alone.

### Accessibility (decision 11)

On the delegate:
- `readonly property string accessibleName`, built from kind, title and `statusText` ("run: CI, failed" or "repository: owner/name, 2 running"), with "expanded" or "collapsed" appended for rows that can expand.
- `Accessible.role: Accessible.ListItem`, `Accessible.name: accessibleName`, `Accessible.selected: index === root.cursor`, `Accessible.focusable: true`.
- The smoke test reads these back from a delegate (`item.Accessible.role`, `.name`, `.selected`, `.focusable`) and checks `.selected` changes with the cursor. Decision 11 asks for the properties to be covered, and a string test alone would pass with them unwired.

The list gets `Accessible.role: Accessible.List`, and the search field gets `Accessible.name: "Search repositories"` (its placeholder disappears as soon as you type). Names are plain strings, so they carry the model's already-cleaned text.

The smoke test checks `accessibleName` first, since it is what feeds `Accessible.name`, and then the attached values. If reading an attached property from the test QML fails on this Qt version, the plan records that and keeps the string check. It does not drop decision 11.

## Alternatives rejected

- **Put the error back in the footer, or keep it in the placeholder.** The footer is a key hint, and the placeholder disappears as soon as you type or focus the field (the bug). The owner chose a separate line.
- **Count repositories with a `runs` array for the coverage note.** Nearly every repository has one after the first activity check, while finished runs are loaded for only the few you opened. It would make the note read "complete" when it is not. `summaryAt` is the honest signal.
- **A new success colour or a hard-coded green.** The theme has none, and hard-coded colours break the theme-native rule. Decision 9 chose icon and label.
- **Use `Color.muted` for queued, skipped and neutral.** It would help at a glance, but the owner's decision asks only that success and running differ. It would also change selected-row contrast on every theme. Left for #43, which already revisits the status colours.
- **Show unmapped status strings as they are.** They are unsanitised GitHub text. The table plus "unknown" is safer, and the set is small.
- **An in-panel keys overlay for `?`.** It would copy the key list into QML, and it must be kept in step with `keybindings.sh` and the README. The menu entry already works and closes the panel the same way.
- **`wl-copy` through `bash -c`, as Omarchy's own panels do.** It needs shell quoting. The plugin's rule is argument arrays only.
- **`Quickshell.execDetached` for copy, as `xdg-open` does.** It gives no sign when `wl-copy` is missing, so the panel would say "Copied" when nothing was copied. A `Process` costs about ten lines and tells the truth.
- **A fixed 8-row page.** It is the bug. Row heights differ.
- **A screen-reader test setup now.** There is none in the repo, and decision 11 chose properties plus the smoke test. A manual Orca check is a possible follow-up (Orca is installed here), but it is not part of the work.
- **Keep the job-fetch stamp until #41 ships its replacement.** The owner ordered #42 after #41, so the replacement exists when this lands.
- **Re-fetch to get fields.** Every field shown is already in the data. No new requests.

## Risks

- **The stamp is the only age of job data until #41 lands.** If #42 were merged first, there would be nothing showing it. The order in decision 12 prevents this. The plan checks that #41 is merged before the subtitle step.
- **Dropped `#run_number`.** People refer to runs by number. It is not in decision 2's list, so it goes. It is a one-line change to bring back, in the subtitle or the title.
- **Title can still be cut at very narrow widths.** The caps (branch 28, actor 16, event 14, my choice) reserve room but do not guarantee it. A long title elides at the right, as today. The visual check at the narrowest width settles whether the caps are enough.
- **Behaviour changes users may notice.**
  - Right on an open row now moves to its first child instead of closing it. The README documented the old behaviour.
  - Ctrl and Alt combinations no longer act.
  - Page keys move a different number of rows.
  - Search no longer closes open repositories, and the empty search field no longer shows the error.
- **Hidden expanded runs keep their expanded flag, and the cap does not bound them.** `recent()` (`Polling.js:141`) exempts any run `kept()` (`:146-148`) protects from the ten-completed-run cap. Codex reproduced 50 retained completed runs with expansion flags against 10 without. Before, any filter edit cleared the flags. Now a run you opened and filtered away stays protected. The count is bounded only by how many runs the user opens, and the scheduler budget still limits fetches. The retention policy for runs no longer listed is #41's. The plan must confirm #41 covers it, or raise it with the owner. It does not change decision 5.
- **`wl-copy` behaviour not checked.** It forks into the background to hold the selection, and I expect the parent to exit 0 with its pipes closed, so `Process.exited` fires. I did not run it from Quickshell. If the process stays attached, the notice would not appear. A started process does not prove the clipboard was set, so the plan must not report "copied" on start. It must stop and ask the owner.
- **`y` clash with #45** (see Interaction). A message in the plan or the #45 spec fixes it. It is not a bug in this change.
- **Screen readers are untested.** I cannot say Quickshell exposes layer-shell windows to AT-SPI on this setup. The properties are set and asserted, and nothing more is claimed.
- **Modifier guard and key mapping have no automated test** until #47 adds real key events. `tests/qml-smoke.py` calls panel functions (`panel.move`, `panel.expand`); it does not send keys. The guard is one early return, and the manual check below covers it.
- **Quota shown is per credential, not per repository.** It is the core rate-limit window as of the last reply, and hidden after the reset time. The helper reads `x-ratelimit-remaining` only, not the limit, so the panel cannot show "of 5,000". Adding `x-ratelimit-limit` is a one-line helper change if the owner wants it. My own account showed 2,427 left of 5,000 during this check.
- **Stale comment.** `ActionsPanel.qml:201` names Quickshell 0.3.1. I will correct it only if the failed-start behaviour check on razer shows it has changed.
- **Hosts.** Every host that runs the panel gets the same change. There is no per-host setting. razer is the one with a real Omarchy session for the manual check. p510 is not involved, so no build or deploy decision is needed there.
